# Кузя: Алмазная лихорадка — ремастер

Перенос **Hugo: Black Diamond Fever** на **Godot 4**. Первый этап объединяет
проверенный импорт ресурсов Windows-версии и небольшой игровой маршрут,
на котором можно проверять управление, камеру и графику.

**Состояние: `0.1.0-dev`.** Проект запускается и позволяет пройти тестовый
берег: собрать 12 алмазов, преодолеть препятствия, активировать контрольную
точку и добраться до выхода. Этот маршрут создан для разработки; исходный
уровень игры пока не восстановлен целиком.

## Уже работает

- Контроллер персонажа: движение относительно камеры, ускорение, бег,
  прыжок переменной высоты, небольшой допуск после схода с края и буфер прыжка.
- Камера от третьего лица: вращение, приближение и проверка препятствий.
- Алмазы, счётчик, таймер, контрольная точка, возвращение после падения,
  завершение маршрута, пауза и повторное прохождение.
- Импорт оригинальной модели Кузи и пальмы из `HUGO4.CD`.
- Запуск без оригинальных ресурсов: используются собственные учебные модели.
- Разбор MDIC, текстур RGBA, звуков WAV, каталогов сцен и геометрии type 2001.
- Проверки повреждённых данных, целостности геометрии и игрового поведения.

Оригинальные модели, текстуры, музыка, видео и установочные файлы игры
подключаются из локальной копии. Они не входят в репозиторий. Автоматической
загрузки игры и запуска её EXE в инструментах нет.

## Быстрый запуск

Нужен [Godot 4.7.2 Standard](https://godotengine.org/download/archive/4.7.2-stable/).
Версия .NET не требуется. Откройте `game/project.godot` и нажмите **F5**
для запуска проекта.

Из командной строки:

```sh
godot --editor --path game
godot --path game
```

Имя исполняемого файла Godot в системе может отличаться от `godot`.
Без импорта проект сразу работает на учебных моделях.

## Подключение оригинальной графики

Нужны Python 3, NumPy, Pillow и файл `HUGO4.CD` из Windows-версии игры.
Проверенная русская копия имеет размер **42 946 560 байт** и SHA-256:

```text
fac39256dfdeedc4b19e07c171048e8c4e72a4fbe37cb4a8b8791239972aaa58
```

```sh
python -m venv .venv
# Windows:
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python tools/import_original.py "D:\Games\Hugo\HUGO4.CD" --project-root .
```

Для Linux/macOS используйте `.venv/bin/python` вместо `.venv\Scripts\python`.
Повторно откройте проект в Godot, чтобы он импортировал созданные GLB.

Импортер создаёт `game/assets/generated/hugo.glb`, `palm.glb`,
`hugo_body.glb` и `asset_manifest.json`. Промежуточные данные находятся в
`.work/`. Оба каталога исключены из Git. Повреждённый контейнер не должен
заменять ранее успешно импортированные ресурсы.

Исходная текстурированная модель нормализуется до высоты персонажа 1,7 м.
Оригинальная кадровая деформация сохранена как morph targets в отдельном
GLB тела; точные тайминги, переходы и воспроизведение оригинальных анимаций
ещё не перенесены. Движения в прототипе процедурные.

## Управление

| Действие | Клавиатура и мышь | Геймпад |
|---|---|---|
| Движение | WASD / стрелки | Левый стик |
| Прыжок | Пробел | A / нижняя кнопка |
| Бег | Shift | Правая верхняя кнопка |
| Вращение камеры | Удерживать ПКМ | Правый стик |
| Приближение | Колесо мыши | — |
| Вернуться к контрольной точке | R | — |
| Пауза | Esc | Start |
| Полный экран | F11 | — |

Собранные алмазы сохраняются после падения. Команда «Начать заново» в меню
сбрасывает маршрут, таймер, алмазы и контрольную точку.

## Проверки

```sh
python -m unittest discover -s tests -v
godot --headless --editor --path game --import
godot --headless --path game --fixed-fps 60 --script res://tests/smoke_test.gd
```

Графическая проверка с сохранением кадра требует видеодрайвер:

```sh
godot --path game -- --capture=/absolute/path/scene.png
```

Проверки выполняются локально. GitHub Actions не настроен.
Подробности и границы проверки: [docs/status.md](docs/status.md).

## Сборка для Windows

В Godot установите стандартные экспортные шаблоны той же версии.
Затем экспортируйте профиль **Windows Desktop** либо выполните:

```sh
godot --headless --path game --export-release "Windows Desktop" ../builds/Hugo_Remaster_Prototype.exe
```

Перед экспортом импортируйте оригинальные ресурсы, если они нужны в сборке.
Экспортные файлы находятся в игнорируемом `builds/`.
