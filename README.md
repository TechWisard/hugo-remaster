# Кузя: Алмазная лихорадка — восстановление на Godot

Перенос Windows-версии **Hugo: Black Diamond Fever** на **Godot 4.7.2**.
Версия проекта — **0.4.0-dev**. Импортер восстанавливает все восемь игровых
глав, исходные объекты, анимации, камеры, события, звук и видеоролики.
Главное меню запускает кампанию от вступления до финального ролика и титров.

Графика использует оригинальные модели и поддерживает отдельный набор из
шести улучшенных текстур окружения. Добавлены MSAA 2×/4×/8×, SSAA, фильтрация
HD-поверхностей с mipmaps и анизотропией. Для Windows подготовлена внешняя
интеграция **DLSS 5 Neural Rendering** через GITC-Uplift/ReShade с проверкой
совместимости и запуском обычного рендера при недоступности NR.
Контакты и часть рендера обслуживает Godot: совпадение с оригинальным EXE
не объявляется побитовым или полным. Новых HD-моделей пока нет.

## Новое в 0.4

- Раздельный выбор языка текста и озвучки с сохранением настроек и живым
  обновлением меню, HUD, подсказок и диалогов. Подключены **16 языков**:
  русский, английский, датский, шведский, норвежский, финский, французский,
  испанский, итальянский, португальский, нидерландский, немецкий, чешский,
  венгерский, словацкий и польский.
- 111 авторских строк нового интерфейса на каждый язык и по 205 извлечённых
  строк оригинальных изданий. Названия глав берутся из проверенных исходных
  таблиц, если установлен языковой пакет.
- Оригинальные аудиовизуальные ролики: 128 назначений, 101 уникальный OGV.
  Язык выбирается для целого ролика; при повреждении или отсутствии файла
  используется целая доступная резервная версия. Искусственного дубляжа нет.
- Отдельный `Hugo_Languages.pck` содержит языковые данные и обновляется
  независимо от EXE. Без него игра запускается с базовой оригинальной дорожкой.
- Ускорен поиск узлов при загрузке, устранено ненужное чтение массивов вершин,
  неизменившиеся зоны столкновений переиспользуются. HUD обновляет цифры только
  при изменении значений; 355 звуковых ID используют 131 общий ресурс данных.
- Добавлен проверяемый бинарный кэш JSON, предварительное построение HD mipmaps
  и освобождение неиспользуемых HD-текстур в режиме «Оригинальные».
- Профили «Качество», «Баланс», «Скорость», масштаб 3D от 50% до
  200% при независимом полном разрешении интерфейса и отчёт производительности
  по явному параметру запуска.

## Возможности 0.3, сохранённые в 0.4

- «Продолжить» сохраняет текущий прыжок, падение, удар и неуязвимость;
  первый новый удар после загрузки больше не теряется.
- Исправлены ползание/прыжок на подъёмах и двойной расход жизни после
  запоздавшего события смертельной области на фабрике.
- Восстановлены исходный отдельный граф тени Кузи, уменьшение тени в прыжке
  и совместное мигание персонажа/тени после урона.
- Улучшенные текстуры подключаются по исходным пикселям и переключаются
  обратно на оригиналы без изменения игровых моделей и анимаций.
- Поддерживаются Full HD, QHD, 4K, 16:10, ultrawide и произвольный размер
  окна. Полный экран использует родное разрешение монитора. UI масштабируется
  равномерно, а неподтверждённая смена режима отменяется через 15 секунд.
- Настройки изображения сохраняются; внешний NR необязателен для запуска
  игры на AMD, Intel и NVIDIA. Для Windows включён резервный ANGLE/D3D11.

## Восстановлено

- 2 514 объектов в восьми главах: размещение, вложенные графы, все действия,
  движущиеся платформы и декорации.
- 14 действий Кузи и 27 отдельных анимаций гибели на особых поверхностях;
  исходные деформации вершин, трансформации и временные шкалы.
- Отдельная исходная тень: постоянная фаза, native inverse-multiply blend,
  масштаб по высоте и общая с персонажем маска мигания.
- Параметры движения, прыжка и ползания, физические размеры тела. Удары,
  подбор и контактные события используют исходные зоны столкновений.
- Таблицы состояний: переходы, здоровье, таймеры, сообщения, скрытые бонусы,
  контрольные точки и выходы из глав.
- Исходная collision-геометрия, свойства поверхностей и движущиеся тела.
- Пути камеры, CSnapTracker, исходная перспектива и событие встряски.
- Загрузка двух соседних участков, плоскости переключения по камере и
  исходные диапазоны включения объектов; состав участков сохраняется.
- Частицы: текстурные кадры, цвета, размеры, направления, время жизни и пулы.
- Четыре исходных режима mesh-материалов; 285 последовательностей текстур,
  190 анимаций цветов и 8 анимаций UV с исходными фазами и округлением.
- 355 WAV-ресурсов, последовательности звуков и 113 источников окружения.
- Семь сюжетных роликов, исходная видеозаставка ITE, восемь музыкальных
  дорожек и титры при их подключении.
- Пауза, выбор глав, звук, сложность новой игры, сохранения и резервная копия.

В Git находятся код, проверки и документация. Оригинальные ресурсы,
установочные EXE, сборки с ними и производные скриншоты в Git не входят.
Импортер читает локальные файлы и не запускает EXE игры.

## Запуск

Нужен [Godot 4.7.2 Standard](https://godotengine.org/download/archive/4.7.2-stable/),
без .NET. Откройте `game/project.godot` и нажмите **F5**.

```sh
godot --editor --path game
godot --path game
```

Без оригинальных ресурсов меню предлагает отдельный авторский тестовый
маршрут из версии 0.1. Он не выдаётся за исходный пляж.

## Импорт

Нужны Python 3, зависимости и `HUGO4.CD` из Windows-версии. Проверенная
русская копия: **42 946 560 байт**, SHA-256:

```text
fac39256dfdeedc4b19e07c171048e8c4e72a4fbe37cb4a8b8791239972aaa58
```

```sh
python -m venv .venv
# Windows:
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python tools/import_original.py "D:\Games\Hugo\HUGO4.CD"
```

В Linux/macOS используйте `.venv/bin/python`. По умолчанию импортируется
вся кампания. `--previews-only` оставляет профиль проверки трёх моделей.

Для роликов установите **FFmpeg** и передайте каталог с `CUTSC*.BIK` и `ITEMEDIA.BIK`.
Дорожки `Track02.ogg` … `Track09.ogg` подключаются из отдельного каталога:

```sh
python tools/import_original.py "D:\Games\Hugo\HUGO4.CD" --media-dir "D:\Games\Hugo" --music-dir "D:\Games\HugoMusic"
godot --headless --editor --path game --import
godot --path game
```

Параметры медиа необязательны. Отсутствующие файлы не заменяются посторонними.
Конверсия сохраняет исходные размеры, частоту кадров и соотношение сторон.
Проверенные предыдущие конверсии используются повторно только при совпадении
хешей исходника и результата.

Результат находится в `game/assets/generated/`, промежуточные данные —
в `.work/`. Оба каталога исключены из Git. Неудачный импорт сохраняет
предыдущий комплект. Исходники держите вне этих управляемых каталогов.

## Управление

| Действие | Клавиатура / мышь | Геймпад |
|---|---|---|
| Движение | WASD / стрелки | Левый стик |
| Прыжок | Пробел | A |
| Удар | E / ЛКМ | X |
| Присесть / ползти | Ctrl | B |
| Свободная камера | ПКМ и мышь | Правый стик в режиме орбиты |
| Исходная камера / орбита | C | — |
| Приближение свободной камеры | Колесо мыши | — |
| Вернуться к контрольной точке | R | — |
| Пауза | Esc | Start |
| Полный экран | F11 | — |
| Пропустить ролик | Пробел / Esc | A / B |

В исходных главах цифровое направление уже даёт максимальную исходную
скорость; Shift её не увеличивает. В тестовом маршруте Shift сохраняет бег.
На обычной сложности стартуют четыре жизни всего; HUD показывает три запасные.
После гибели мир и алмазы откатываются к контрольной точке, жизнь расходуется,
здоровье восстанавливается. R возвращает к точке без расхода жизни.

## Windows

Установите экспортные шаблоны Godot той же версии и импортируйте ресурсы:

```sh
godot --headless --path game --script res://tools/compile_runtime_cache.gd
godot --headless --path game --script res://tools/build_language_pack.gd -- --language-pack-output=/absolute/path/builds/Hugo_Languages.pck
godot --headless --path game --export-release "Windows Desktop" ../builds/Hugo_Remaster.exe
```

Профиль включает JSON-манифесты, необязательный бинарный кэш, титры и
установленный HD-набор. Языки экспортируются отдельно: поместите
`Hugo_Languages.pck` рядом с EXE. В автоматическом NR-пакете достаточно одной
копии файла рядом с `Launch-Hugo.cmd`; чистая игра в `clean/` найдёт его там. Оригинальный
импорт содержит 582 ресурса плюс `asset_manifest.json`; HD-набор учитывается
отдельно. Проверка экспорта и её точные результаты описаны в
[validation.json](docs/validation.json). Запуск встроенного PCK через Linux
не заменяет нативную проверку Windows и настоящего NR на RTX.

Обычный Godot-релиз не требует NVIDIA и DLSS. Пакет внешней интеграции запускается
через **Launch-Hugo.cmd**: сначала проверяется реальный рендерер, затем подходящий
NR-путь. При неподдерживаемой карте/драйвере, неудачной пробе NR или сбое этого
пути используется чистая копия игры с обычным сглаживанием и HD-текстурами.
Полная схема, зависимости и ограничения — в
[инструкции интеграции](integrations/dlss5/README.md).
