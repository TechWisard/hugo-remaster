# Восстановленная физика движения Кузи

Оригинальная кампания читает параметры движения из record типа 10000.
`tools/hugo_assets/player.py` декодирует их в `native_player.movement`,
`HugoPlayer.set_native_configuration` подключает этот профиль перед добавлением
персонажа в сцену. Без профиля используется прежний контроллер тестовой сцены.
Оригинальные EXE и DLL не запускаются.

## Исходные параметры и единицы

Все восемь персонажей исследованной русской версии содержат одинаковые значения
этих полей. Масштаб геометрии — `0.01`; исходный таймер — 300 единиц в секунду.
Конструктор `0x401CAF–0x401D2F` делит скорости на 300 для интеграции по единицам
таймера. Декодер сохраняет исходные float, смещения и адреса доказательств.

| Поле record | Значение | Значение в Godot | Назначение и подтверждение |
|---|---:|---:|---|
| `+0x68` | 825 | 8.25 ед./с | Максимальная наземная скорость, `0x404978–0x404983` |
| `+0x6C` | 390 | 3.9 ед./с | Порог выбора действий walk/run, `0x404AED–0x404B06` |
| `+0x70` | 0.05 | 0.05 за tick | Приближение наземной скорости к цели, `0x404A20–0x404A97` |
| `+0x7C` | 300 | 3.0 ед./с | Ползание, `0x403603–0x40360E` |
| `+0x80` | 0.9 | 0.9 за tick | Приближение скорости в приседе, `0x40365F–0x40370D` |
| `+0x8C` | 300 | 3.0 ед. | Высота прыжка, конструктор `0x404400` |
| `+0x90` | 900 | 9.0 ед. | Расстояние для расчёта горизонтальной скорости прыжка |
| `+0x94` | 0.8 | 0.8 с | Авторская длительность прыжка |
| `+0x98` | 0.01 | 0.01 за tick | Управление в прыжке, `0x404606–0x40465D` |
| `+0xAC` | 300 | 3.0 ед./с | Целевая горизонтальная скорость отдельного состояния падения |
| `+0xB0` | 0.005 | 0.005 за tick | Управление при падении, `0x403E30–0x403E87` |
| `+0xB4` | 72 | 216 ед./с² | Ускорение отдельного состояния падения, `0x403E98–0x403EA1` |
| `+0xB8` | 900 | 9.0 ед./с | Максимальная скорость падения, `0x403EA4–0x403EC1` |

`+0x6C` не является отдельной скоростью ходьбы. Оригинал умножает `+0x68` на
величину аналогового ввода, затем выбирает визуальное действие по порогу.
Цифровая клавиша направления запрашивает полную скорость. Отдельного
ускорителя sprint в обработчике `0x4018C0–0x401A46` нет, поэтому Shift в
оригинальной кампании не увеличивает 8.25. В тестовой сцене прежний бег сохраняется.

## Дискретная траектория прыжка

Конструктор `CHugoStateJump` (`0x404412–0x404449`) вычисляет:

```text
n = trunc(duration_seconds * 300) / 2  (целое деление)
initial_velocity_per_tick = 2 * height / (n + 1)
gravity_per_tick_squared = initial_velocity_per_tick / n
```

При исходных значениях `n = 120`; вертикальная скорость равна
`600 / 121` source units/tick. В единицах Godot это примерно
`14.876033` ед./с, ускорение — `37.190083` ед./с². Каждый tick сначала
прибавляет текущую скорость к положению, затем уменьшает скорость на ускорение
(`0x404660–0x404675`). Сумма первых 120 приращений равна исходной высоте 300.

При входе в прыжок оригинал дополнительно поднимает положение на одну source
единицу (`0.01` Godot), а горизонтальную скорость умножает на отношение скорости
прыжка к наземной (`0x404898–0x4048D8`). Целевая скорость в воздухе равна
`900 / 0.8 = 1125` source units/s, то есть 11.25 в Godot. Отпускание кнопки не
увеличивает гравитацию в восстановленной ветке: такого сокращения траектории
в разобранном состоянии прыжка нет.

Нисходящая половина обычного прыжка продолжает использовать эту параболу.
Отдельное состояние падения включается, если персонаж оказался на 300 source
единиц ниже начальной высоты прыжка (`0x404765–0x404794`) либо сошёл с опоры.
У него другие управление, гравитация и ограничение скорости. Подмена всей
нисходящей половины прыжка параметрами этого состояния резко сократила бы
исходную дальность.

Runtime накапливает целые шаги по 1/300 секунды, суммирует исходные приращения
и передаёт итоговое перемещение в Godot один раз за физическое обновление.
Затем сохраняет конечный импульс и ограничения, полученные от столкновений.

## Наземная поверхность и размеры тела

Наземная рекуррентная формула — `v = target * response + v * (1-response)`.
На обычной поверхности `response=0.05`. При отпускании ввода тот же коэффициент
тормозит движение; если квадрат скорости стал меньше исходных `0.1`
в tick-единицах, скорость обнуляется (`0x404243–0x404265`). В масштабе и единицах
Godot порог квадрата скорости примерно `0.9`.

Поле поверхности `+0x10` изменяет поведение. При коэффициенте меньше единицы
оригинал ограничивает response меньшим из него и базового значения. При
коэффициенте от единицы наземное движение делит целевую скорость на него
(`0x4049EA–0x404A20`). Для приседа применяется только ограничение response.
Мир передаёт значения методом:

```gdscript
set_native_surface(response_coefficient: float, prevents_standing: bool)
```

Флаг поверхности `+0x18` не позволяет выйти из уже принятого приседа, пока он
активен (`0x4035C4–0x4035E9`, `0x40374E–0x403773`). Автоматический переход
стоящего персонажа в присед по этому флагу не установлен.

Урон поверхности (`+0x0C`) преобразуется в целое и передаётся HealthBar событием
`0x22000003` (`0x403008–0x403024`). Если персонаж выжил, оригинал переводит его
в прыжок (`0x403054–0x403094`); мир вызывает `bounce_from_native_surface` после
одного принятого нелетального попадания. При смерти поле поверхности `+0x14`
выбирает отдельный death effect (`0x403035–0x40304C`).

Сброс персонажа задаёт box `(-40,-40,0)..(40,40,300)` в source axes
(`0x4021D8–0x402240`). Текущая высота физического тела равна 300 стоя и 200
в приседе (`0x4043D3`, `0x4038C6`). Поэтому используется BoxShape3D шириной и
глубиной 0.8, высотой 3.0 или 2.0. Визуальная модель высотой около 3.33077
не переопределяет этот объём.

## Проверка и границы точности

Синтетические Python-тесты проверяют дискретную высоту, перевод единиц,
изменение длительности и отклонение неверных параметров. Оригинальные байты
в репозиторий не добавляются.

Изолированная проверка Godot при 60 физических обновлениях в секунду прошла
16 проверок с реальными Input/physics: размеры тела и приседа, устойчивое
касание пола, наземные скорость и сумма перемещений, отсутствие добавленного
sprint, прыжок после короткого нажатия, торможение, запрет вставания поверхностью
и ограничение отдельного падения. Подъём составил `3.0099947`, включая исходное
поднятие на 0.01. При полной начальной скорости дальность до обновления,
на котором подтверждён пол, составила `9.1875`; это значение зависит от
момента разрешения контакта, а не новая авторская константа дальности.

Восстановлены формулы свободного движения и параметры. Разрешение контактов,
наклоны, перенос платформой и потолки обслуживает Godot; исходный collision
solver целиком не переносился. Малое прилегание к полу `0.03` — настройка Godot,
а не восстановленный параметр. Современный слой ввода нормализует диагонали,
что отдельно отличается от исходного преобразования байтов ввода. Полный
контроллер переходов, поворот и редкие состояния ещё требуют отдельной проверки.

## Движущаяся платформа и возврат к checkpoint

Перенос проверен в настоящем дереве экспортированного уровня: исходный
`CPlatform`, его путь и bounds, дочерний `AnimatableBody3D` и восстановленный
контроллер Кузи. На трёх исходных платформах персонаж сохранял касание пола
все 120 проверенных обновлений за две секунды. Платформы прошли соответственно
0.668, 9.964 и 42.986 единицы; для быстрого движения относительное отставание
не превысило одного физического обновления. Это граница Godot integration,
а не доказательство побитового совпадения с исходным collision solver.

Проверка реального checkpoint после `g044_o0128_t10402` обнаружила сохранённую
в CharacterBody ссылку на предыдущую платформу. После телепорта Godot повторно
добавлял её скорость, смещая персонажа на 1.15 единицы без ввода. Первое
`move_and_slide` после `respawn` теперь выполняется с временно отключённым
переносом платформы и `PLATFORM_ON_LEAVE_DO_NOTHING`, затем обычные настройки
восстанавливаются. Повторная проверка дала нулевое горизонтальное смещение
и устойчивое приземление на checkpoint. Параметры исходного движения не менялись.

Постоянный тест использует установленный локально оригинальный campaign export:

```bash
godot --headless --fixed-fps 60 --path game --script res://tests/native_platform_test.gd
```
