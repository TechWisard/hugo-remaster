# Производительность — 0.4

Оптимизация сохраняет исходные события, движение, частоту физики 60 Гц и
порядок обработки столкновений. Уменьшение графической нагрузки выбирается
отдельно в настройках. Единого FPS для любых карт, драйверов и разрешений
этот проект не обещает.

## Что изменено

- Поиск сотен владельцев сцены заменён одним обходом и индексом точных имён.
  При повторяющемся имени сохраняется первый depth-first match.
- Признак vertex color импортированных ArrayMesh читается из формата
  поверхности без копирования всех массивов вершин, UV и других атрибутов.
  Для примитивов Godot сохранён совместимый путь чтения массива поверхности.
- Коллизионные OBB переиспользуются, если action, мировая трансформация,
  необходимые фазы исходных треков и физические флаги не изменились.
  Скрытие, выключение, новая поза и переход состояния инвалидируют кэш.
  Порядок пар и немедленное обновление при переходе состояния сохранены.
- HUD форматирует и присваивает счётчики при изменении значений, часы —
  при изменении целой секунды. Переводы читаются один раз; смена языка
  обновляет существующие элементы по сигналу.
- 355 исходных WAV ID разделяют 131 неизменяемый AudioStream по SHA256.
  У каждого проигрывания отдельные loop/pitch/gain и exclusive-group правила.
- Текстуры неподходящего размера не требуют чтения пикселей ради поиска HD.
  Mipmaps готовятся до запуска. При переходе к оригинальным текстурам
  неиспользуемые HD-ресурсы освобождаются; живые внешние владельцы сохраняются.
- Необязательный бинарный кэш JSON проверяется по SHA256 исходника и payload,
  ограничению размера и типу данных. Повреждённый/устаревший кэш возвращает
  обычное чтение JSON. Данные восьми глав не удерживаются отдельным глобальным
  кэшем после выгрузки.
- Языковые видео не загружаются в память заранее. Общие файлы хранятся один
  раз, а различающийся видеоряд разных дубляжей остаётся самостоятельным.

## Профили изображения

| Профиль | MSAA | Внутренний размер 3D | Текстуры |
|---|---:|---:|---|
| Качество | 4× | 100% | HD, где установлены |
| Баланс | 2× | 100% | HD, где установлены |
| Скорость | Выкл. | 75% по каждой оси | Оригинальные |
| Свой | Выбранное значение | 50/67/75/100/150/200% | Выбранный набор |

При выходном 3840×2160 профиль «Скорость» рисует сцену в 2880×1620,
то есть 56,25% исходного числа пикселей; интерфейс остаётся в выходном размере.
Уменьшение числа пикселей не означает такое же увеличение FPS: ограничивать
кадр могут CPU, синхронизация или другой этап рендера.

Compatibility использует bilinear scaling. FSR1/FSR2 в Godot требуют Forward+;
эта настройка не выдаётся за FSR или DLSS. См. официальные страницы
[масштабирования](https://docs.godotengine.org/en/stable/tutorials/3d/resolution_scaling.html),
[оптимизации 3D](https://docs.godotengine.org/en/stable/tutorials/performance/optimizing_3d_performance.html)
и [импорта изображений](https://docs.godotengine.org/en/stable/tutorials/assets_pipeline/importing_images.html).

Внешние NR-профили сохраняют свои проверенные требования к MSAA/масштабу.
Выбор профиля не меняет размер окна, язык, физику, звук и сохранённый прогресс.

## Сборка оптимизированных ресурсов

После импорта оригинальных данных и установки необязательного HD-набора:

```sh
godot --headless --editor --path game --import
godot --headless --path game --script res://tools/prepare_hd_imports.gd
godot --headless --editor --path game --import
godot --headless --path game --script res://tools/compile_runtime_cache.gd
```

Mipmap-подготовка сохраняет lossless-пиксели и не включает скрытое уменьшение
HD-текстур или необратимое сжатие. Без предварительного шага остаётся
совместимый путь построения mipmaps при загрузке. Cache в
`game/assets/runtime_cache/` воспроизводится из точного JSON; исходники
и кэш исключены из публичного Git.

После импорта языков пакет строится отдельно:

```sh
godot --headless --path game --script res://tools/build_language_pack.gd -- --language-pack-output=/absolute/path/Hugo_Languages.pck
```

В пакет попадают только проверенные хешами OGV, текстовые JSON и манифест.
Его отсутствие не препятствует запуску основной игры.

## Измерение на своём компьютере

В Windows можно запустить обычный EXE с явным отчётом:

```bat
Hugo_Remaster.exe -- --level=g006 --performance-report=performance.json --performance-frames=1800
```

Поиграйте после загрузки. После 60 прогревочных кадров монитор собирает 1800
интервалов активной игры и сохраняет mean/p50/p95/p99/max времени кадра,
снимки draw calls, память, размер и параметры рендера, адаптер и драйвер.
Пауза и загрузка исключаются. Игра продолжает работать; монитор не завершает
её. Без этого параметра узел измерений вообще не создаётся.

Это интервалы кадров Godot, включая ожидание VSync и работу драйвера.
Они не измеряют отдельно GPU-время и не подтверждают число нейронно
сгенерированных кадров. Успех NR требует собственного журнала интеграции.

Для воспроизводимых разработческих замеров всех восьми глав:

```sh
godot --headless --fixed-fps 60 --path game --script res://tests/performance_benchmark.gd -- --benchmark-out=/absolute/path/cpu_benchmark.json
```

Headless измеряет CPU-часть без отрисовки. Графические проверки здесь выполнены
через Mesa llvmpipe, программный OpenGL. Они проверяют фактические кадры и
поведение опций, но не заменяют измерения NVIDIA/AMD/Intel на Windows.

Точные результаты, методика и границы сравнения находятся в
[validation.json](validation.json). Измеренный выигрыш отдельной операции
не переносится автоматически на общий FPS.

## Измерения экспортированных сборок 0.3 и 0.4

Сравнивались реальные embedded PCK обеих Windows-сборок через matching Linux
Godot 4.7.2. На каждую версию — три свежих процесса, поочерёдный запуск,
восемь глав, 60 кадров прогрева и 180 кадров выборки на главу. Игрок оставался
в обычной стартовой позиции. Другие задачи рендера и тестирования не запускались.
Это headless CPU/wall-замер на одном хосте с общими ресурсами, без GPU; кеш ОС не очищался.
В первоначальном прогоне seed не фиксировался. В таблице — медианы p50 трёх прогонов,
а не частота кадров, которую получит Windows-игрок. Меньшее время лучше.

| Глава | 0.3 p50, мс | 0.4 p50, мс | Изменение времени |
|---|---:|---:|---:|
| Пляж | 4.744 | 4.176 | -12.0% |
| Старая тропа | 4.003 | 3.790 | -5.3% |
| Алмазная пещера | 5.530 | 5.435 | -1.7% |
| Линия поддержки | 6.304 | 6.754 | +7.1% |
| Нефтяная вышка | 5.124 | 5.293 | +3.3% |
| Алмазная фабрика | 3.688 | 3.623 | -1.8% |
| Переплавка | 4.391 | 4.139 | -5.7% |
| Побег | 5.302 | 4.466 | -15.8% |

В шести главах медиана уменьшилась, в двух выросла. Разброс заметный;
данные не подтверждают обещание, что каждый уровень стал быстрее.
Статическая память движка в снимках восьми глав уменьшилась на **11,3–12,0 МиБ**.
Это счётчик выделений Godot, не общий RSS процесса и не видеопамять.

### Повторная проверка «Линии поддержки»

Самый заметный случай проверен отдельно: одинаковый `seed(24680)`, 60 кадров
прогрева, 1200 кадров измерения, три последовательные пары свежих процессов.
Состояния активных графов до и после выборки совпали во всех шести запусках.

| Метрика: медиана трёх прогонов | 0.3, мс | 0.4, мс |
|---|---:|---:|
| p50 | 7,870 | 8,576 |
| p95 | 24,778 | 22,351 |
| Среднее время | 10,881 | 10,625 |

p50 ухудшился, p95 и среднее улучшились; две из трёх отдельных пар p50
улучшились. Это смешанный результат, который не доказывает стабильную
регрессию именно кэша коллизий и не позволяет объявлять главу быстрее.

### Изолированные операции

| Проверка | До | После | Что означает |
|---|---:|---:|---|
| Пляж: 500 refresh всей группы при неизменной позе | 190,006 мс | 62,321 мс | 3,05× для этой операции |
| Линия поддержки: тот же тест | 387,105 мс | 98,110 мс | 3,95× для этой операции |
| Базовые ресурсы 355 WAV ID | 355 | 131 | Меньше дублирующихся AudioStream |
| Статическая память в отдельном аудиотесте | 4 175 400 байт | 3 814 420 байт | Экономия 360 980 байт |

Для refresh взяты медианы 15 испытаний на версию: три процесса по пять
повторений. Поза намеренно не менялась. В настоящей стартовой сцене «Линии
поддержки» большинство активных объектов движется: за 1200 кадров получено
19 200 пересчётов и 1 207 повторных использований, около 5,9% попаданий.
Поэтому выигрыш 3–4× нельзя переносить на время игрового кадра.

Аудиотест повторён пять раз на стратегию. Загрузка/дублирование заняло
53,492 мс до и 55,213 мс после, с пересекающимися диапазонами. Его результат —
сокращение числа ресурсов и памяти; ускорение загрузки звука не доказано.

Хеши сборок, исходные значения, повторный seeded-прогон и границы выводов
сохранены в [validation.json](validation.json). Аппаратные FPS Windows,
качество и стоимость нейрорендеринга этими измерениями не устанавливаются.
