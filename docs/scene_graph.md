# Исходные сцены, размещение объектов и коллизии

Этот документ описывает восстановленные данные **Hugo: Black Diamond Fever**.
Код находится в `tools/hugo_assets/scene_graph.py` и `levels.py`. Импортер
использует локальный `HUGO4.CD`; исходные файлы, извлеченные модели и результаты
рендеринга в репозиторий не входят. EXE исследовался статически, без запуска.

## Что действительно восстановлено

Экспорт собирает восемь игровых локаций из их собственных записей объектов,
трансформов и ссылок на модели. Он не раскладывает все найденные модели в сетку
и не назначает им придуманные позиции. Неиспользуемый ресурс модели остается
неразмещенным.

Проверенная русская версия `HUGO4.CD` имеет SHA-256
`fac39256dfdeedc4b19e07c171048e8c4e72a4fbe37cb4a8b8791239972aaa58`.
Использованный для проверки соглашений EXE `HUGO4_PC.EXE` имеет SHA-256
`bbd9c5a756ab63c1585284c63e5315b6ca1628b953d8f474f87d8f3a750b5cd3`.

Проверка всего контейнера охватывает 81 группу: одну глобальную, 18 основных
сцен и 62 подсцены. Меню и видеосцены тоже учитываются при проверке ссылок,

1 406 графов, 3 337 состояний, 12 843 слота узлов, 7 754 ссылки на трансформы

графы событий. Эти числа **не означают**, что все экземпляры должны быть
одновременно видимы: runtime выбирает одно действие каждого объекта.

## Иерархия сцен и scoped references

Категория находится в младшем 16-битном слове scene payload по смещению 8:

| Категория | Значение |
|---|---|
| 2 | Глобальная группа 0 |
| 3 | Основная сцена |
| 4 | Подсцена предыдущей основной сцены |

Для категории 3 число подсцен находится по смещению 28, а их размеры —
в таблице с 32. Размер каждого дочернего payload вместе с внешним MDIC
заголовком проверяется модулем `catalog.py`. `SceneIndex` запрещает
перекрывающиеся группы и подсцены без родителя.

У категории 4 поля payload `+16/+20` содержат абсолютные MDIC offsets
предыдущей и следующей подсцены; 0 означает конец цепочки. Все 124 поля
62 подсцен проверены: цепочки линейны и не выходят из основной сцены.
В level JSON они представлены как `segments[].previous_group/next_group`,
с исходными offsets, `owner_ids`, bounds и `first_segment_group`.
Дополнительный статический анализ `CScopeManager`, `CSceneScopeProxy` и
`CActorManager` восстановил окно максимум двух сегментов, начальную загрузку
первого, переключение по camera planes и независимые actor progress ranges.
`scopes.py` проверяет main header tables и добавляет `native_scope_policy`;
в экспортированных `segments` поле `native_residency_policy_decoded` равно
true. Подробный protocol, checkpoint lifecycle и VA приведены в
[scopes.md](scopes.md). Точная асинхронная задержка чтения CD не выводится
из ресурсов.

Ссылка — little-endian `uint32`:

```text
0                         null
word & 0x80000000          признак ссылки
word & 0xffff             индекс записи в целевой группе
(word >> 16) & 0x7fff      число переходов к родителю
```

Scope 0 означает текущую группу; scope 1 — ее родителя; scope 2 — родителя
родителя. Это не абсолютный номер группы. Например, в g008 объект 125
ссылается по полю `+12` значением `0x80010000` на mesh g006/r0000. Попытка
считать scope 1 глобальной группой разрешила бы эту ссылку в scene descriptor,
что несовместимо с полем визуального ресурса. Все разобранные ссылки
подтверждают переходы `subscene → main scene → global`.

`SceneIndex.resolve()` проверяет признак ссылки, границы индекса, доступную
глубину родительской цепочки и, когда это требуется, тип целевой записи.

## Трансформы и единицы

Типы 3000–3003 хранят одинаковую начальную аффинную часть:

| Смещение | Поле |
|---:|---|
| 0 | Идентификатор типа |
| 4 | Translation, 3 × float32 |
| 16 | Matrix, 9 × float32, по строкам |

Преобразование точки: `world = matrix @ local + translation`.
Для массива строк это `vertices @ matrix.T + translation`.
Композиция родителя и локального трансформа:

```python
matrix = parent.matrix @ local.matrix
translation = parent.matrix @ local.translation + parent.translation
```

Соглашение подтверждено функцией `0x40BDE0–0x40BE44`: первая выходная
координата — произведение строки из смещений 0, 4, 8 на входные X, Y, Z;
следующие строки начинаются с 12 и 24. При запросе коллизии `0x414AD0`
вычитает translation, транспонирует матрицу через `0x40BCD0`, затем вызывает
этот множитель для перехода в локальные координаты.

Базис сохраняется без принудительной ортонормализации. В исходнике существуют
50 матриц, которые не проходят строгий тест ортонормальности; это не повод
отбрасывать их или менять форму объекта. Проверяются конечность элементов
и невырожденность матрицы.

Переход к системе GLB/Godot:

```python
output = (source_x, source_z, -source_y) * 0.01
```

Преобразование базиса сохраняется отдельно от вершин. GLB использует общие
локальные mesh buffers: world matrix расположен на owner-узле, а составной
локальный matrix — на дочернем узле модели. Runtime может менять owner или
его анимацию без повторного применения уже запеченного трансформа.

Анимационные хвосты 3001/3002/3003 разобраны в `animation.py`; см.
`animation.md`. Manifest содержит также оба пути CTargetCam: поле `+0x1c`
и альтернативный путь `+0x28`. Последний нужен CSnapTracker, даже когда
он не является текущим world transform камеры.
Экспорт включает все transform records групп уровня, в том числе пути,
на которые ссылаются только параметры событий: например, g069/r0007 для
Getaway camera effect `0x22000009`.

## Embedded graph

Смещения ниже отсчитываются от начала графа, если не указано другое.

| Смещение | Поле |
|---:|---|
| 0 | `0x01010101` |
| 4 | Нулевое служебное слово |
| 8 | Число состояний N |
| 12 | Число слотов узлов M в каждом состоянии |
| 16 | Относительное смещение state table: `32 + 48*M` |
| 20, 24 | Нулевые служебные слова |
| 28 | Смещение области runtime slots: 32 |
| 32 | M × 48 байт runtime slots; не исходные world matrices |

State descriptor занимает 56 байт:

| Смещение в descriptor | Поле |
|---:|---|
| 0 | `0x02020202` |
| 4 | Ноль |
| 8 | Native flags |
| 12 | Native duration, float32 |
| 16 | Сохраненный вектор из трех float32; семантика не назначается |
| 28 | Bounds min/max, шесть float32 |
| 52 | Указатель на строку узлов, **относительно этого descriptor** |

У каждого состояния ровно M записей по 32 байта. Пустые записи тоже
содержат `0x03030303`; они не являются концом массива. Начало строки
состояния i проверяется как `nodes_base + i*M*32`. Например, у Hugo
g006/r0183 primary graph находится по `0x634`; N=14, M=8,
первый descriptor расположен по `0x7d4`, а его строка — по `0xae4`.

| Смещение в node | Поле |
|---:|---|
| 0 | `0x03030303` |
| 4 | Ноль |
| 8 | Transform reference или 0 |
| 12 | Ноль |
| 16 | Renderable reference или 0 |
| 20 | Первый native collision mask |
| 24 | Второй native collision mask |
| 28 | Относительный к node указатель на шесть float32 collision bounds, либо 0 |

Поле `+24` **не является числом дочерних узлов или числом bounds**.
Его чтение прослежено через `0x415F10 → 0x415CD0 → 0x4176D0`, а первый
mask — через `0x415CB0 → 0x4176B0`. Типичные пары: тело Кузи `0x1001/8`,
удар `2/4`. Для совместимости Python-поля `flags` и `aux_count` остаются,
но семантические свойства называются `collision_mask_a/b`.

Все 3 022 ненулевых указателя `node+28` адресуют конечные, упорядоченные
шестикомпонентные bounds. Эти указатели не используются как ссылки на
иерархию. Трансформы слотов находятся в пространстве владельца; дополнительная
композиция возникает при явной ссылке на вложенный граф 8003.

## Native terrain collision

Тип 10400 получает collision object из mesh visual, а не автоматически
делает твердыми все декоративные полигоны. Связка проверена в constructor
`0x405960`, mesh interface getter `0x42C420` и инициализации
`CQuadTreeCollD` `0x4165C0/0x4166B0`.

В mesh типа 2001 поле `+52` указывает на корень collision quadtree после
native timeline. Ноль означает отсутствие дерева. Смещения в этом разделе
абсолютны относительно начала mesh-записи.

**Quad node, 36 байт:**

| Смещение | Поле |
|---:|---|
| 0 | `minX, minY, maxX, maxY`, четыре float32 |
| 16 | Четыре указателя дочерних узлов; 0 — отсутствует |
| 32 | Указатель листовой таблицы или 0 |

**Лист:** `uint32 entry_count`, затем `uint32 table_pointer`; таблица
следует непосредственно за этими восемью байтами.

**Запись листа, 12 байт:**

| Смещение | Поле |
|---:|---|
| 0 | `uint16 surface_type` |
| 2 | `uint16 triangle_count` |
| 4 | Указатель на исходный submesh header |
| 8 | Указатель массива `uint16` индексов треугольников этого submesh |

Алгоритм поиска `0x414BE0` выбирает XY-ячейку. Функция `0x414530` перебирает
12-байтные записи, берет face buffer по `submesh+12`, vertex buffer по
`submesh+16` и декодирует те же три 10-битных индекса, что используются
рендером. Это доказывает точную связь collision triangles с исходной
геометрией. Повторение треугольника в нескольких ячейках учитывается один раз
при построении физического mesh; дерево и все ссылки сохраняются отдельно.

Проверены все 61 дерево контейнера: 2 436 узлов, 1 801 лист,
33 758 ссылок и 16 763 уникальных треугольника. В игровых сценах 59 деревьев,
32 210 ссылок и **16 009 уникальных collision triangles**. Два оставшихся
дерева относятся к меню/финальным титрам.

У segment `g058_o0008_t10400` исходный указатель равен нулю. Экспорт сохраняет
`collision_geometry: "none_in_source"`; придуманная коллизия из render mesh
не добавляется. Платформы 10402 используют отдельные явные bounds и данные
формы из `gameplay.py`; декоративные объекты 10401 не становятся твердыми
из-за наличия видимой модели.

`surface_type` связывается с 20 материалами сегмента из `record+0x9c`
с шагом 52 байта; см. `gameplay.md`. Экспорт сохраняет числовые ID, в том
числе 0, 1, 2, 5, 6, 10, 15, 16, 17. Он не выводит название поверхности
из ее текстуры. Исходные damage/traction fields декодируются отдельно.

Нативный алгоритм является поиском высоты по XY с информацией о поверхности.
Использование восстановленных треугольников в Godot не доказывает идентичность
всей физики, разрешения контактов или правил передвижения оригиналу.

## Камерный фон и camera visual

Тип 2000 — `CCameraVisual`, constructor `0x42C430`. Это не потерянная модель.
Его камера и projection parameters передаются через gameplay metadata.

Тип 10403 — `CBackmap`. Render handler `0x405720` на событие `0x22020005`
ставит визуальный ресурс в позицию текущей камеры, добавляет offset,
временно меняет дальнюю дистанцию и после отрисовки восстанавливает projection.

| Поле owner | Значение |
|---:|---|
| `+8` | Mesh reference |
| `+0x10` | Поворачивать offset вместе с yaw камеры |
| `+0x14` | Временная дальняя дистанция в исходных единицах |
| `+0x18` | Offset XYZ |

Единственный такой игровой owner — g006/r0238: mesh g006/r0006,
offset `(0,0,0)`, yaw flag 0, distance 10000. Он экспортируется в группу
`Background` с `render_policy: "camera_centered"`. Runtime должен следовать
этой политике; мировое положение `(0,0,0)` не является авторским положением неба.

## Контракт экспорта и runtime

```python
campaign = export_campaign(catalog, output_directory)
```

Функция создает `campaign.json`, а также `levels/g006.glb`,
`levels/g006.json` и аналогичные пары для остальных семи сцен. Пути в JSON
относительны output directory. Функция работает внутри временного staging
каталога и не перезаписывает существующую кампанию. Публикацию всего набора
assets выполняет внешний импортер.

`campaign.levels[]` содержит `id`, `main_group`, `source_name`, `groups`,
`geometry_path`, `manifest_path`, SHA-256 GLB, world bounds, terrain bounds,
spawn и validation counters. Spawn взят из world transform owner типа 10000.

Owner ID стабилен: `g007_o0028_t10400`. Он содержит source group, индекс
record и класс. Owner-узел GLB имеет то же имя. В owner manifest доступны:

- `position`, `source_position`, `matrix`, `source_matrix`, `bounds`;
- `source_provenance` с record/payload/container offsets;
- `category`, `class_name`, `collision_role`, `render_policy`;
- `world_transform_ref`, `mesh_nodes`, `mesh_instances`, `actions`;
- `collision_mesh_key` и `collision_geometry` для исходных сегментов.

Группы сцены: `Static`, `Actors`, `Triggers`, `Background`, `Other`.
Owner с графом содержит дочерние группы `<owner_id>_Action000`,
`<owner_id>_Action001` и т. д. Имена глобально уникальны внутри GLB, а не только
среди соседних узлов. Это необходимо, поскольку Godot при импорте glTF
переименовывает повторяющиеся имена во всем документе: общие `Action000`
у разных owners превращались в другие имена и нарушали точную привязку.

В `actions[]` сохраняются исходные `index`, duration, flags, native
descriptor offset, bounds и mesh node names. Переименование не меняет
source action index и не пересчитывает его по порядку узлов после импорта.
Например, исходное действие 3 экспортируется так:

```json
{
  "index": 3,
  "node_name": "g070_o0108_t10300_Action003",
  "node_path": "g070_o0108_t10300/g070_o0108_t10300_Action003"
}
```

`node_name` — точное имя дочернего узла owner, `node_path` содержит owner
и этот дочерний узел. GLB и manifest используют одну строку имени.
`NativeActorMotion` привязывает действие через
`owner_visual.get_node_or_null(action.node_name)` и хранит его по исходному
числовому `index`. Отсутствующий узел, повторный index или привязка двух
действий к одному узлу дают явную `binding_error` и останавливают обновление
motion. Runtime не угадывает автоматически добавленные суффиксы и не
подбирает узел по похожему имени.

Экспортер до публикации проверяет глобальную уникальность всех GLB node
names, точное совпадение action имени/пути и принадлежность action своему
owner. Результат отражен в `validation.glb.checked_unique_node_names` и
`validation.glb.checked_action_node_paths`. Для выбранного source action index,
присутствующего в `actions[]`, runtime включает **ровно соответствующую группу**;
отрицательный visual action скрывает все группы. Событийные графы `Triggers`
остаются скрытыми до активации.

В каждом action также находятся `collision_nodes` для всех слотов, включая
узлы без renderable. Они сохраняют обе collision masks, bounds в исходных
и GLB координатах, source offsets и `transform_chain`. Bounds находятся
в **пространстве самого узла**: chain еще не применен; world owner matrix
добавляется один раз снаружи. Альтернативные действия имеют свои masks и
bounds. `root_motion_vector`, `root_motion_source_vector`,
`root_motion_length`, `phase_domain` и `cycle_distance` позволяют runtime
использовать исходный пространственный вектор и distance-based phase.

Каждый `mesh_instances[]` содержит `name`, `action`, `source_mesh`,
`transform_chain`, `stored_samples`, `timeline_words`, `timeline_loop`.
Трансформы по ключам вида `g006_r0020` находятся в
`native_transform_tracks`. Данные morph samples остаются в GLB. Менять
видимость `<owner_id>_Action###` можно без повторной загрузки общей mesh
geometry; `mesh_instances[].action` продолжает содержать исходный числовой
индекс действия.

`native_collision_meshes[key]` содержит `faces` — по три локальные
GLB/Godot точки на треугольник, `surface_types`, `source_triangles`,
`source_quadtree` и проверочные счетчики. Физический объект, построенный из
этих точек, должен наследовать **owner transform**, а не получать его дважды.

## Эмиттеры, спрайты и исходные частицы

`effects.py` разбирает все 164 ресурса CEmitter типа 7500 и связанные с ними
ресурсы CPSXSprite (2002) и particle pool (7000). Вместимость всех исходных
pools составляет 5610 частиц. В восьми игровых главах используются 69
определений, 1109 action anchors и 42 уникальных изображения. GLB сохраняет
anchor как именованный Node3D под соответствующим действием; JSON хранит
`effect_instances` с owner-local `transform_chain` и `effect_definitions`
с параметрами, provenance и относительными путями к PNG. Изображения
сохраняют исходные RGBA bytes; повторное чтение PNG сверяется побайтно.

Тип 7500 подтвержден веткой фабрики `0x42018F/0x4201EC`, конструктором
`0x4255F0` и RTTI `CEmitter`. Заголовок занимает 104 байта. Значимые поля:

| Смещение | Подтвержденные данные |
| --- | --- |
| `+0x04`, `+0x10` | Scoped references на sprite 2002 и pool 7000 |
| `+0x18..0x1D` | Начальный RGB, конечный RGB |
| `+0x20` | Частиц в секунду |
| `+0x24` | Начальный остаток времени эмиссии, в исходных данных 0 |
| `+0x2C` | Полуугол конуса в градусах |
| `+0x34` | Радиус диска рождения в исходных единицах |
| `+0x38/+0x3C` | Время жизни: base / percent |
| `+0x40/+0x44` | Скорость: base / percent |
| `+0x48/+0x4C` | Вращение: base / percent, обороты за 0.06 секунды |
| `+0x50/+0x54` | Конечный размер: base / percent |
| `+0x58/+0x5C` | Начальный размер: base / percent |

Слова `+0x28`, `+0x60`, `+0x64` сохранены без придуманного назначения.
`sample_native_spawn` воспроизводит десять последовательных случайных
выборок из `0x425710`: end size, start size, lifetime, spin, initial angle,
disk azimuth, disk radius, velocity azimuth, cone cosine, speed. Native
random нормализован делением на 32767. Разброс равен
`base * (u * (100 - percent) + percent) / 100`: percent задает один конец
интервала до 100 процентов, а не симметричный допуск. Значения выше 100
также допустимы и встречаются в исходных ресурсах.

Точка рождения лежит в локальной плоскости XY: радиус `sqrt(u) * radius`,
азимут `2*pi*u`. Направление конуса — локальная +Z;
`cos(theta) = cos(half_angle) + u * (1 - cos(half_angle))`.
Позиция и скорость затем преобразуются исходной матрицей узла; translation
применяется только к позиции. Счетчик рождения равен
`floor(rate * (dt + remainder))`; новый остаток равен
`dt + remainder - emitted / rate`. Заполненный pool прекращает рождение.

У типа 7000 заголовок 40 байт, затем `capacity` записей по 76 байт и
массив индексов по 4 байта. Упакованные смещения и capacity проверяются
строго. Начальное число активных частиц равно нулю. Обновление `0x425BE0`
уменьшает lifetime на `dt`, удаляет истекшую частицу, умножает velocity на
поле `+0x20`, вычитает поле `+0x24` из native Z velocity и прибавляет
`velocity * dt` к позиции. **Множитель скорости и вычитание gravity
применяются на обновление без умножения на dt.** Цвет и размер линейно
интерполируются по возрасту и округляются к нулю до integer: RGB сохраняется
в bytes (`0x425D44/0x425D7B/0x425DB2`), размер — в int32 (`0x425E19`).
Angle остается float и в оборотах увеличивается на
`dt * 16.666666 * sampled_spin`. Точная частота legacy update loop этим
ресурсом не задается и пока не подтверждена. Выбор частоты современным
runtime нельзя выдавать за доказанный исходный clock.

Тип 2002 содержит последовательность texture references и режим смешивания.
Подтверждение: CPSXSprite constructor `0x423410`, преобразование command mode
`0x411010`, D3D blend states `0x410B43`. Режим 1 умножает destination на
`1 - source RGB`, 2 складывает source и destination, 3 использует обычное
source-alpha смешивание. Кадр выбирается по
`min(floor(age_fraction * frame_count), frame_count - 1)`. У используемых
игровых emitter sprites по одному кадру; общий parser поддерживает
проверяемые многокадровые ресурсы. В отдельном particle draw path цвет
нормализуется как `RGB / 128`: байт 128 задает нейтральную модуляцию.
Обычные PC mesh materials используют собственный draw path с `RGB / 255`;
доказательства приведены в [mesh_materials.md](mesh_materials.md).

Отрисовка `0x425EA0` строит billboard, обращенный к экрану. Исходный радиус
в пикселях равен `size * (1/256) * 480 * focal / view_depth`, то есть
диагональный world radius — `1.875 * size` исходных единиц. Сторона quad
равна этому радиусу, умноженному на `sqrt(2)`. При нулевом угле углы лежат
на направлениях `(-r,0)`, `(0,+r)`, `(0,-r)`, `(+r,0)`: для обычного
квадрата это дополнительный поворот 45 градусов. Texture aspect ratio
в исходном particle quad не применяется. Pixel focal подтверждается
camera setter `0x4138F0`, а accessor `0x4165B0` возвращает поле camera+0x0C.
Современный renderer может отличаться от исходного в clipping и
перенасыщении цвета; эти различия не исправляются выдуманными параметрами.

## Материалы, лимиты поверхностей и проверки

Исходные terrain meshes могут содержать больше 256 submeshes. Прямой перенос
каждого из них в отдельную Godot surface приводил к `MAX_MESH_SURFACES` и
потере геометрии при импорте. Экспортер объединяет primitives с одинаковыми
отрисовываемыми материалами и полным исходным словом render flags, сохраняя
COLOR_0, UV и каждый morph delta. Animated material parts остаются отдельными
surfaces: одинаковый первый texture frame не делает разные последовательности
одним материалом. Для RGB/UV-анимации UV2 хранит исходные vertex/part indices.
Вершины не свариваются. Индексы меняются только на смещение присоединенного
vertex buffer. Сравнивается каждый атрибут каждого исходного треугольника
и каждого morph sample до и после операции.

Если после объединения остается больше 128 surfaces, mesh разбивается на
дочерние части под исходным именованным узлом. Структура owner и его
provenance не теряется. У проверенных восьми сцен максимум равен 47 surfaces
на mesh. Валидация GLB дополнительно проверяет буферы, индексы, изображения,
morph counts и world placement после сериализации matrices.

Материалы используют unlit/double-sided представление. Ordinary PC mesh RGB
нормализуется по 255, UV — умножением на float32 `1/255`. Восстановлены четыре
native mesh blend selectors, generated vertex alpha и alpha-test cutoff
`8/255`; additive и inverse-source-color modes выполняет runtime adapter.
`material_animation_manifest.json` содержит все 285 texture sequences,
190 RGB-animated parts и 8 UV-animated parts. Runtime выбирает texture frame
по visual phase, а RGB/UV — по native mesh timeline; первоначальные samples
в GLB служат стартовыми данными. Исходные vertex IDs в UV2 позволяют точно
сопоставить массивы после Godot import. Подробный контракт и доказательства:
[format_notes.md](format_notes.md) и [mesh_materials.md](mesh_materials.md).
Native culling correspondence, lighting и полная transparent sorting
остаются ограничениями восстановления.
Для частиц восстановлены исходные данные и update equations; legacy clock
и три неиспользованных поля emitter остаются неподтвержденными.

Дополнительный graph Hugo по указателю `record+0x0C` ресурса типа 10000 —
**наземная тень**. Конструктор сохраняет relocated pointer в том же runtime
поле (`0x401BEA–0x401BFD`); render event `0x22020005` задаёт ему pose и
рисует вместе с основным персонажем (`0x402F59–0x402F93`). Его state и phase
остаются нулевыми. Все восемь auxiliary расположены по смещению 6684 и
содержат один узел с identity transform, статичной плоскостью из четырёх
вершин и двух треугольников и одной и той же текстурой 64×64. Native material
selector 2 реализуется через inverse-source-color adapter.

Manifest уровня сохраняет `auxiliary_graph_offset` и
`auxiliary_graph_render_policy: native_ground_shadow`; validation считает
`player_shadow_graphs`. Граф экспортируется отдельно в
`animations/hugo_shadow.glb` и описывается в `animation_manifest.json.hugo_shadow`.
Он не добавляет действия в основной граф и не размещается как неподвижная
декорация уровня. Мировую позу ему задаёт presentation-контроллер игрока.

Исходная поза тени сохраняет X/Y и basis render transform персонажа,
заменяет Z на cached floor `actor+0x24C` и масштабирует basis на
`1 / (1 + float32(0.0045) * (actor_z - floor_z))`
(`0x402EF8–0x402F63`, константа `0x43E444`). Повторная нормализация высоты
модели и минимальный размер отсутствуют. Тень не выравнивается по нормали
поверхности. Пол исходник ищет в XY: `0x4211E0` берёт наибольшую высоту
из четырёх точек `(x±50,y±50)` source units. Godot-адаптер проверяет четыре
вертикальных запроса к native colliders вокруг ног и выбирает самое высокое
попадание ниже ног. Это современная адаптация; полный legacy collision
solver и его обработка платформ/ступеней не воспроизводятся.

Основная модель и тень разделяют native blink по маске `0x20` оставшихся
единиц таймера 300 ticks/s (`0x402F66–0x402F93`). Исходник исключает state 6
и pending-death flag `actor+0x4C4` из мигания. Значение последнего прослежено
до смертельного отбрасывания (`0x402833`, `0x403A49–0x403A88`), но полный
переход через смертельное отбрасывание пока не объявляется восстановленным.
Детали экспорта, формулы, visibility policy и границы Godot-адаптации —
в [animation.md](animation.md).

**27 графов смерти от поверхностей** имеют другой источник: их указатели
находятся в `CDefaultSegment` типа 10400 по адресу
`0x9C + surface_type * 52 + 0x14`. `animation.py` экспортирует их в отдельные
`animations/surface_death_*.glb` и связывает с исходной поверхностью через
`animation_manifest.json.surface_deaths`. `original_level.gd` вызывает
`player.play_death_for_surface(group, record, offset)` при соответствующей
смерти. Их активация подтверждена native death entry `0x403C36..0x403C4C`
и render replacement `0x402E2B..0x402E93`. При таком replacement ранний выход
из рендера исключает и обычную модель, и её тень; runtime скрывает тень
во время `surface_death_*`. См. [animation.md](animation.md).

Synthetic tests не содержат данных игры. Они проверяют ancestor scopes,
относительные state pointers, corruption/cycles, аффинную композицию,
вложенные модели, глобально уникальные имена действий разных owners,
сохранение source action indices и точные manifest/GLB paths, reuse geometry,
material/morph batching,
128-surface splitting, native collision face bounds, ссылки соседних
сегментов и отсутствие частичной публикации при неудачном экспорте.
Тесты эффектов проверяют pool layout, scoped sprite references, исходные
spawn equations, percent > 100 и точный RGBA roundtrip. Команда:

```sh
python -m unittest discover -s tests -v
```
