# Геометрия, материалы и проверка набора 0.6

Улучшенная геометрия собирается отдельно от исходных ресурсов. В игре сохраняются
исходные владельцы объектов, игровые события, UV-развёртки, фазы анимаций и
идентификаторы контактных поверхностей. Переключение качества меняет отображаемые
меши и материалы на уже существующих объектах.

Для сборки нужен локальный импорт исходной кампании. Чистый checkout без игровых
ресурсов продолжает запускать демонстрационную сцену; команда ниже не скачивает
игру. Исходные GLB, изображения и промежуточные меши не следует добавлять в Git.

## Воспроизводимая сборка

Команды выполняются из корня репозитория. `godot` должен указывать на используемый
локальный исполняемый файл Godot.

```bash
python -m pip install -r tools/requirements.txt
python tools/build_geometry_quality.py --output .work/geometry_base --resume
python tools/complete_geometry_shells.py \
  --input .work/geometry_base/index.json \
  --output .work/geometry_shells
python tools/finalize_boundary_mapping.py \
  --input .work/geometry_shells/index.json \
  --output .work/geometry_final
godot --headless --path game --script res://tools/import_geometry_quality.gd -- \
  --geometry-input="$PWD/.work/geometry_final/index.json" \
  --geometry-output=res://assets/hd/models
```

Первый этап читает все GLB, перечисленные в кампании и манифесте анимаций.
`--resume` использует только результаты с совпадающими входными массивами,
геометрическими контекстами, исходной коллизией, alpha-масками и версией кода.
Каждый численный файл проверяется по SHA-256 перед повторным использованием.

Второй этап завершает доказанные открытые оболочки. Он работает в отдельном
каталоге и сохраняет базовую сборку неизменной. Для адресных повторных построений
воспроизводится исходный `bake_fingerprint`: отличающиеся координаты, владельцы,
границы, материалы или контактные поверхности останавливают сборку. Неизменные
ресурсы копируются побайтно. Изменённые ресурсы получают новые идентификаторы и
fingerprint. Это позволяет закрыть подтверждённый тонкий колпак фонаря или
изогнутую листовую поверхность, сохраняя проверяемое происхождение результата.
Этап также проверяет число инцидентных треугольников у каждого ребра добавленных
alpha-оболочек. Доказанные дефекты раскроя у коротких UV-рёбер исправляются
повторным построением только затронутых ресурсов; старые дефектные оболочки
не остаются под новыми. Коллизия каждого адресного результата должна побайтно
совпадать с базовой сборкой.

Заключительный небольшой этап задаёт физический масштаб UV всем сторонам
подтверждённой торцевой стены шахты, включая узкие боковые грани. Он сохраняет
координаты, нормали, индексы и коллизию и добавляет отдельную запись происхождения
в цепочку; дорогое построение оболочек повторно не выполняется.

Импортёр создаёт сжатые native `ArrayMesh` в `game/assets/hd/models/`. Рабочий
`geometry_pack.json` записывается после успешной обработки всех ресурсов. Поля
`source_inputs`, `pipeline_sha256`, `replacement_alpha_inputs`, SHA каждого
`.res` и `summary.postprocess_chain` предназначены для проверки сборки перед
экспортом. Каталоги отдельных визуальных проб в поставку не входят.

## Как меняется форма

Органические тела, головы, камни и поверхности рельефа получают округлённую
контрольную сетку и криволинейные PN-поверхности. Точки общей границы материалов
сшиваются только при совпадении всех исходных morph-поз. У корпусов сохраняются
функциональные углы и добавляются реальные скруглённые фаски. Точные плоскости
не подразделяются ради увеличения количества треугольников.

Для деталей с известным назначением существуют отдельные операции:

- Корпус, обтекатель, колёса и механические детали самолёта получают разные
  профили кривизны; крылья, хвост, вывески и эмблемы не сглаживаются одним
  общим правилом.
- Белки и зрачки Кузи получают согласованные округлые границы. Размер,
  положение, направление взгляда и native привязки сохраняются.
- Камни на грунте, рельсы, крепежи, трубы, рамы, приборы и другие подтверждённые
  детали становятся геометрическими объёмами, привязанными к их UV-участкам.
  Повторяющиеся UV не соединяют физически раздельные поверхности.
- Волосы, листья, рамы, цепи и выбранные другие alpha-детали получают оболочки
  с лицевой, обратной и контурной поверхностями. Отверстия маски сохраняются.
  Изогнутые открытые полотна проверяются отдельно от замкнутых тел и
  пересекающихся UV-развёрток.
- Подтверждённый открытый металлический колпак фонаря получает внутреннюю
  поверхность и скруглённый обод во всех уровнях детализации.

Новые вершины несут три исходных native идентификатора и неотрицательные веса,
сумма которых равна единице. Эти данные используются для анимированных цветов
и UV. Округление интерполированного идентификатора из UV2 не применяется.
Меши хранят все исходные morph-позы; их общие границы отсечения включают каждую
позу, поэтому изменение силуэта не должно вызывать исчезновение частей модели.

## Коллизия и подтверждённые открытые края

Когда меняются координаты опорной поверхности, runtime переключает коллизию
вместе с её отображаемой геометрией. Непредставленные исходные контактные
треугольники сохраняются. Декоративная оболочка не превращается автоматически
в новый пол, стену или опасную поверхность.

У двух подтверждённых задних границ — берега и входной части шахты — добавлены
видимые завершения с соответствующими коллайдерами. Они существуют и в режиме
«Оригинал», и в улучшенном режиме. Графический переключатель не возвращает
устранённый выход в пустоту. Новые завершения не закрывают произвольные ямы и
не используют общий невидимый пол. Их контактный тип не назначается опасным.
У нового берегового откоса используется существующий скальный материал того же
уровня. Развёртка идёт непрерывно вдоль берега и вокруг его гребня, с заданным
масштабом в метрах. Повторяемый sampler создаётся только для этого нового меша;
UV и режим адресации соседних исходных поверхностей не меняются.

## Материалы и память

Улучшенные материалы используют mipmaps и анизотропную линейную фильтрацию.
Для непрозрачных и обычных alpha-материалов учитываются нормали и освещение
сцены при сохранении исходных вершинных цветов. Специальные additive/inverse
режимы сохраняют свои уравнения смешивания.

Старая цветовая карта не используется как скрытая подложка «HD»-материала.
Функциональная исходная alpha-маска может оставаться отдельным каналом там,
где она задаёт разные коэффициенты прозрачности. Манифест и аудит различают
полноценную замену, отсутствие ресурса и сознательно выбранный режим
«Оригинал».

Лимит размера текстур выбирает исходную авторскую карту или её уменьшенную
копию. Лимиты 512/1024/2048 относятся к новым картам; они не переключают игру
на старые изображения. Native `.tres`-текстуры получают цепочку mipmaps при
первом разрешении ресурса, даже если у их класса нет импортных параметров PNG.

Глобальные кэши изображений и мешей удерживают слабые ссылки. Живые владельцы
сохраняют только реально используемые ресурсы. У анимированных материалов
есть собственный сильный кэш уже запрошенных кадров: цикл не декодирует
каждый PNG заново. Смена качества, размерного лимита или манифеста очищает
этот банк; удаление владельца освобождает его. Остальные главы и все возможные
анимационные клипы не загружаются при старте кампании.

LOD используют индексы общего массива вершин. Промежуточный уровень сохраняет
округлённую форму; переход к более грубой сетке учитывает измеренную ошибку
кривизны и исчезающего объёма. Коллизия соответствует опорной геометрии, а не
случайно выбранному дальнему LOD. Количество байтов изображений и native
ресурсов в отчётах не следует выдавать за полную память видеодрайвера.

## Проверка готового набора

```bash
godot --headless --path game --script res://tools/audit_texture_coverage.gd -- \
  --strict --report="$PWD/.work/texture_coverage.json"
godot --headless --path game --script res://tools/audit_geometry_quality.gd -- \
  --geometry-with-levels --geometry-report="$PWD/.work/geometry_coverage.json"
godot --headless --path game --script res://tests/native_texture_animation_cache_test.gd
godot --headless --path game --script res://tests/native_geometry_quality_test.gd
```

Первый аудит проверяет реально назначенные материалы всех доступных GLB,
каждый кадр анимированных материалов и восемь живых глав, включая независимые
профили эффектов. Он обнаруживает отсутствующую замену, обход адаптера,
старый sampler, отсутствующие mipmaps и повреждённую прозрачность.

Второй аудит проверяет реальные mesh bindings, исходные идентификаторы новых
вершин, morph-массивы, границы отсечения, индексы LOD, освобождение сцен и
согласованную коллизию. Плоские и непреобразованные ресурсы указываются отдельно.
Техническая полнота не является автоматическим подтверждением художественного
качества: нужны одинаковые камеры и позы, просмотр силуэтов, UV, освещения и
движения в самой игре.

Для измерения CPU существуют сопоставимые сценарии:

```bash
godot --headless --fixed-fps 60 --path game --script res://tests/performance_benchmark.gd -- \
  --benchmark-level=g036 --benchmark-quality=original --benchmark-frames=180 --benchmark-rounds=3 \
  --benchmark-out="$PWD/.work/cpu_original.json"
godot --headless --fixed-fps 60 --path game --script res://tests/performance_benchmark.gd -- \
  --benchmark-level=g036 --benchmark-quality=enhanced --benchmark-frames=180 --benchmark-rounds=3 \
  --benchmark-out="$PWD/.work/cpu_enhanced.json"
```

Отчёт содержит отдельный профиль native обновлений цветов/UV и объём
переписываемых атрибутов. Профилирование выключено при обычной игре. Эти команды
не измеряют GPU FPS. Повторяемость CPU-сравнения требует отсутствия других
тяжёлых процессов и программного GPU-рендера во время замера.
