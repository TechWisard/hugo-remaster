# Состояние восстановления — 0.2.0-dev

Восстановлены данные **всех восьми игровых глав** Windows-версии и полная
последовательность кампании: логотип ITE, вступление, меню, главы,
промежуточные ролики, финал и титры. Главы используют исходную геометрию,
модели и текстуры. Тестовый берег версии 0.1 сохранён отдельно.

Это работающая реконструкция на Godot с проверками исходных правил и
данных. Полное совпадение старого движка, ручное прохождение всех маршрутов
и новая HD-графика этим этапом не заявляются.

Количество owners не равно числу видимых врагов: сюда входят камера,
триггеры, фон, коллизии, источники звука, декорации и автоматы состояний.
Повторения ресурсов сохраняются через references/instances.

На обычной сложности стартуют четыре жизни всего и десять единиц здоровья.
HUD показывает запасные жизни. После гибели мир и алмазы откатываются к
исходной контрольной точке. Современное продолжение хранит отдельный более
полный снимок, включая actor phases и native camera pose.

Выход не требует собрать все алмазы. Квалификация ≥90% перезаписывается
результатом нового прохождения. За посещение всех контрольных точек
при завершении главы начисляется одна жизнь с пределом 20.
Завершённое продолжение не начисляет награду повторно.
Сохранение во время смерти не отменяет и не удваивает расход жизни.

## Проверки

Среда исполнения: Godot **4.7.2 Standard**, Linux x86_64. Основные runtime
тесты создают настоящие SceneTree, тела Godot Physics и исходные уровни.
Графические проверки выполняются через OpenGL Compatibility / Mesa llvmpipe.

| Проверка | Что она доказывает |
|---|---|
| Python unit + original E2E | Строгий разбор контейнера, ссылок, геометрии, анимаций, событий, scopes и медиа; полный импорт оригинала |
| `campaign_smoke.gd` | Все восемь исходных стартов и полов, native configuration, сбор предметов, контрольная точка, hidden pickup; точное связывание и переключение всех 3 113 actor action groups |
| `native_route_test.gd` | Все 60 участков в обе стороны, unload/load, gates, checkpoint membership; реальные выходы в 8 из 8 глав |
| `campaign_flow_test.gd` | Полная последовательность глав/роликов, финал, награды, replay и completed resume |
| `native_life_test.gd` | Урон, invulnerability, lethal bypass, native death timing, сохранение во время смерти и game over |
| `native_platform_test.gd` | Реальный движущийся CPlatform, перенос стоящего игрока и сброс контакта после телепорта |
| `native_material_test.gd` | Текстурные последовательности, RGB/UV-фазы и независимость экземпляров |
| `native_vm_test.gd` | Native переходы, timer flags, action phases, logical collision masks и state snapshots |
| `native_scopes_test.gd` | Source policy, JSON number conversion, два участка, диапазоны и checkpoint protocol |
| `save_state_test.gd` | Снимки, раздельные checkpoint/current states, backup recovery и повреждённые поля |
| `media_smoke.gd` | Реальное декодирование OGV, исходные размеры/аспект и однократный пропуск |
| `smoke_test.gd` | 64 проверки тестового маршрута; также отдельный checkout без оригинальных ресурсов |

Сценарный обход участков проверяет residency и настоящие exit overlaps.
Он перемещает тестового персонажа между заданными позициями и **не является
ручным прохождением** препятствий и врагов от начала до конца каждой главы.
Проверка последовательности фильмов отдельно записывает запрошенные movie IDs;
декодирование проверяется настоящим VideoStreamPlayer.

Дополнительно сопоставлены независимые Python/Godot расчёты native animation,
камеры, движения, частиц и затухания звука. Графические пробы проверяют
режимы смешивания на реальном драйвере. На исходных CPlatform проверено
перемещение стоящего игрока и сброс старого контакта после возрождения.

Точные результаты, размеры, SHA-256 и границы каждого прогона находятся в
[validation.json](validation.json). GitHub Actions не используется.

## Windows и ресурсы

Экспортный профиль создаёт Windows x86_64 EXE со встроенным PCK. Включены
JSON-манифесты, импортированные ресурсы, ролики, музыка и титры. Проверяются
структура PE и содержимое PCK. Из встроенного PCK через тот же Godot в Linux
проверена загрузка 581 ресурса, выполнены 26 604 проверки восьми глав и снят
реальный графический кадр. **Нативный запуск Windows здесь не выполнен**;
проверки Linux не заменяют его.

Публичный Git содержит код, тесты и документацию. Исходные контейнеры,
модели, текстуры, звук, видео, производные скриншоты и сборки с ними
исключены из Git. Импорт использует локальные файлы.

Проверенный русский `HUGO4.CD`: 42 946 560 байт, SHA-256
`fac39256dfdeedc4b19e07c171048e8c4e72a4fbe37cb4a8b8791239972aaa58`.
Структура содержит 81 группу, 2 107 MDIC-блоков, 1 590 текстурных блоков,
355 WAV-блоков и 13 228 объектных записей. Эти полные container counts
включают меню, ролики, UI, повторения и неигровые сцены.

## Оставшиеся границы точности

- Контакты разрешает Godot Physics; исходный XY-height collision solver
  целиком не эмулируется. Быстрые платформы могут показывать задержку
  контакта относительно визуального transform на один физический кадр.
- Материалы не воспроизводят все особенности старого растеризатора.
  Сортировка прозрачных поверхностей, culling, динамическое освещение,
  точность framebuffer и пограничное семплирование могут отличаться.
- Частицы обновляются на физической сетке 60 Гц; source drag/gravity
  зависели от частоты обновлений. Пространственное панорамирование звука
  обслуживает Godot, а не DirectSound.
- Ролики перекодированы из Bink в Theora/Vorbis с исходными размером и
  частотой кадров; результат не побитово равен Bink.
- Native scopes используют заранее подготовленные ресурсы; задержка
  асинхронного чтения старого CD не имитируется.
- Условие активации отдельного auxiliary graph Кузи по `record+0x0C`
  остаётся неподтверждённым. Он отличается от 27 восстановленных графов
  гибели на поверхностях; см. [scene_graph.md](scene_graph.md).
- Графика пока оригинального разрешения. Новые HD-ресурсы в этот этап
  не входят; для их подстановки сохранены стабильные source IDs.

Оригинальные игровые EXE во время анализа, импорта и проверок не запускались.
