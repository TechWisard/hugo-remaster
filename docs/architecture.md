# Архитектура восстановления

## Данные и исполнение

Импортер читает локальный HUGO4.CD, проверяет MDIC и извлекает данные в
промежуточный каталог. Исходный контейнер и игровые EXE не исполняются.
Новый `game/assets/generated/` заменяет предыдущий после полной проверки
файлов и хешей. Ошибка публикации восстанавливает предыдущий комплект.

Godot работает с GLB и JSON. MDIC не разбирается во время кадра. Исходные
номера групп, записей, смещения и хеши остаются в манифестах.

| Слой | Основные файлы |
|---|---|
| Контейнер и геометрия | `mdic.py`, `catalog.py`, `mesh.py` |
| Сцены и размещение | `scene_graph.py`, `levels.py` |
| Анимации | `animation.py`, `original_animation.gd` |
| Поведение | `gameplay.py`, `native_state_actor.gd` |
| Движение Кузи | `player.py`, `player.gd` |
| Действия и пути объектов | `native_actor_motion.gd` |

| Физические столкновения | `original_level.gd`, `native_state_actor.gd` |
| Камера | `native_camera.gd` |

| Частицы | `effects.py`, `native_effects.gd` |

## Координаты и столкновения

Единое преобразование — `(x, z, -y) * 0.01`. Позиции не перецентровываются.
Матрицы, геометрия, пути, скорости, гравитация и коллизии переводятся
согласованно. Нативная матрица действует как `M * v`; цепочка родителей
составляется до единственного преобразования осей.

В кампании визуальная высота Кузи около 3.33, физическое тело имеет исходные
размеры 0.8 × 3.0 × 0.8; при ползании высота 2.0. Размер тела не выводится
из анимируемого меша. Тестовый маршрут сохраняет собственные параметры.

Полы берутся из исходного collision quadtree. Видимые треугольники не
становятся автоматически твёрдыми. Нулевая collision-ссылка также не
подменяется визуальным мешем. Контакты разрешает Godot Physics.

Удары, подбор и сообщения идут через исходные зоны текущего действия.
Сторона A получает сообщение, если `A.mask_b & B.mask_a != 0`.
Обработчик проверяет собственную категорию collider. Один удар имеет
отдельный номер; повторное пересечение не умножает урон.

## Состояния и время

Классы установлены по фабрике и RTTI исходного EXE. Тип 10300 — общий
автомат состояний: враг, механизм или контрольная точка. Роль не
назначается по внешнему виду модели.

Путь меняется при исходном флаге 4. Нулевой временной период останавливает
визуальную фазу. Distance-действия используют расстояние и исходный вектор
цикла. Точный конец фазы 1 сохраняется до следующего обновления CTicker.
Сетка времени движения Кузи — исходные 300 Гц внутри физических кадров Godot.

## Продолжение и контрольная точка

Main и global scopes остаются загруженными; одновременно действуют максимум
два дочерних участка. Плоскости `CSegmentTrigger` проверяют позицию камеры.
Отдельный gate сравнивает диапазон объекта с `trunc(camera.native_phase * 992)`.
Вышедший из диапазона объект приостанавливается; выгруженный участок при
возвращении пересоздаёт исходное состояние с учётом сохранённых removed IDs.
Godot удерживает подготовленные ресурсы в памяти, отключая их отображение,
логику, звук и коллизии. Задержка чтения исходного CD не имитируется.

`user://campaign_v2.json` хранит сложность, жизни, бонусы здоровья, настройки
и состояния глав. Временная запись проверяется перед заменой; предыдущая
корректная версия остаётся в `.bak`. Проверяются схема, размер, известные
главы, типы полей и конечность чисел. Уровень фильтрует неизвестные source IDs.

Современное продолжение между запусками сохраняет состояния, здоровье,
фазы, позы, позицию Кузи и уже прозвучавшие cues. Оба типа снимков сохраняют
состав участков, native phase и позу камеры. Исходная контрольная точка
хранит отдельный снимок удалённых объектов, алмазов, флагов контрольных
точек и позиции возвращения. После гибели потраченная жизнь не возвращается,
здоровье становится максимальным, предметы после точки появляются снова.
Обычные автоматы входят в исходное состояние 0 по восстановленным правилам.
Завершённое прохождение сохраняет отдельный флаг уже начисленной награды:
«Продолжить» возвращает экран перехода без повторной бонусной жизни.
Новый выбор главы создаёт новое прохождение и заново определяет квалификацию
по доле алмазов, как исходный end-of-level handler.

Сохранение во время гибели отдельно фиксирует `death_pending` и уже
потраченную жизнь. Продолжение такого снимка сразу восстанавливает контрольную
точку; последняя потраченная жизнь оставляет экран окончания игры. Поэтому
перезапуск не отменяет смерть и не расходует одну жизнь дважды.

## Рендер

OpenGL Compatibility сохраняет исходные UV, текстуры, цвета и morph samples.
Крупные модели группируются по материалу с проверкой атрибутов каждого
треугольника: это устраняет лимит поверхностей Godot без потери геометрии.
Фон следует камере и рисуется за уровнем. Частицы используют исходные кадры
и blend-режимы. Обычные mesh materials имеют отдельную нумерацию: alpha,
additive, destination × (1 − source) и opaque. RGB/UV у них нормализуются
через 255; отдельный particle color path использует 128.

Анимированные материалы сохраняют texture sequences и native Q12 timeline
для RGB/UV. Исходный индекс вершины проходит импорт через UV2; runtime
создаёт частные изменяемые buffers и материалы, чтобы разные экземпляры
ресурса могли играть разные фазы. Они обновляются тем же visual phase,
что и morph targets, включая однокадровую геометрию с анимацией текстуры.
Полное соответствие старым sorting, culling и framebuffer rules не заявляется.

Будущие модели и текстуры можно назначать по стабильным source IDs, сохраняя
таблицы состояний и траектории. Чистый checkout запускает отдельный
авторский тестовый маршрут без оригинальных ресурсов.
