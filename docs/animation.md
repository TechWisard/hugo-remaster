# Восстановленные движения Кузи

Импортёр восстанавливает 14 действий оригинального персонажа и 27 отдельных
графов смерти от опасных поверхностей: деформации тела, движение головы,
предмета в руке и вложенные преобразования. Godot воспроизводит исходные
таблицы поз и ключи преобразований. Это **vertex animation**, а не
созданный заново скелет. Ни оригинальная программа, ни её библиотеки при анализе
не запускаются.

Отдельно восстановлены исходный граф наземной тени, изменение её размера над
полом и общее с персонажем мигание после урона. Эти данные сохраняются вне
14 действий и 27 графов смерти.

## Что подтверждено

Источник профиля — группа 6, объект 183, тип 10000. Его основной граф содержит
14 состояний и восемь фиксированных слотов на состояние. Ноды графа расположены
в пространстве владельца; вложенный объект типа 8003 добавляет следующий уровень
преобразования. Например, голова проходит через внешний transform и внутренний
объект 158, который ссылается на transform 122 и mesh 121. В экспорте сохранены
все исходные ссылки и SHA-256 объектов.

Назначения действий проверены по статическому дизассемблированию Windows EXE:
классы состояний идентифицированы через RTTI, а их вызовы выбора действия —
через общий метод по адресу `0x403390`. EXE SHA-256:

## Время и путь

У оригинала подтверждён таймер **300 единиц в секунду**. `CDefaultTimer`
получает миллисекунды через `timeGetTime` (`0x41F88F`, IAT `0x43E1B4`), умножает
их на `0.3` и преобразует в целое (`0x41F8B0`). Методы чтения секунд умножают
полученный счётчик на `1/300` (`0x41F8D0`, `0x41F8F0`). Это единица таймера,
**не частота кадров анимации**.

Выбор действия (`0x403390`) устанавливает период в контроллере фазы:

- Для обычных действий используется исходное поле длительности.
- Если установлен младший бит флагов действия, период берётся из длины вектора
  движения. Фаза таких действий продвигается пройденным расстоянием.
- Обновление `0x416090` прибавляет приращение, делённое на период; `0x4161A0`
  задаёт период и его обратную величину.

При масштабе экспорта `0.01` цикл ходьбы соответствует примерно `1.618984`
единицы Godot, бега — `4.456563`, ползания — `1.317716`. При изменении высоты
персонажа эти расстояния умножаются на тот же постоянный масштаб. Неподвижный
персонаж не прокручивает цикл ходьбы по произвольной частоте.

Manifest сохраняет `authored_duration_seconds`, её выражение в единицах таймера,
`phase_domain`, `cycle_distance`, исходный вектор и `animation_fps: null`.
Не следует интерпретировать количество сохранённых поз как FPS.

## Смерть от опасных поверхностей

Запись поверхности внутри объекта типа 10400 содержит по смещению `+0x14`
ссылку на встроенный граф смерти. В исследованном контейнере найдены 27 разных
графов в 19 объектах; каждый содержит одно действие и три меша. Десять графов
имеют исходную длительность около `0.333333` секунды, остальные 17 —
`2.166667` секунды. Ссылки, смещения, длительности и исходные байты сохраняются
в manifest; это дополнительные профили, а не переименования действия 13.

При смертельном уроне поверхности `0x403035–0x40303E` записывает этот указатель
в `actor+0x4C8`. Вход в состояние смерти (`0x403C36–0x403C4C`) получает
длительность действия 0 выбранного графа. Ветка рендера `0x402E2B–0x402E93`
передаёт ему фазу и мировой transform персонажа, затем возвращается до обычного
рендера Кузи. Поэтому runtime заменяет обычную геометрию на выбранный граф и
продвигает его по авторской длительности в секундах. Наличие флага движения
в этих графах не превращает смерть в действие, управляемое расстоянием.

API игрока:

```gdscript
play_death_for_surface(source_group: int, source_record: int, graph_offset: int) -> float
```

Метод возвращает длительность, а завершение сообщает `death_animation_finished`.
Для неизвестной ссылки используется обычное действие 13. Во время отдельного
графа `get_native_visual_action()` возвращает `-1`: обычные области столкновения
графа Кузи к нему не относятся. Физическое тело игрока хранится отдельно.
Ключ `surface_deaths` manifest связывает исходную тройку группа/объект/смещение
с именем клипа, например `surface_death_g011_r0184_o000004e0`.

## Наземная тень и мигание после урона

### Указатель, геометрия и постоянная фаза

Дополнительный указатель `record+0x0C` у типа 10000 ведёт к наземной тени.
Конструктор `CHugoMainActor` прибавляет к нему базу записи и сохраняет
результат в том же runtime-поле `actor+0x0C` (`0x401BEA–0x401BFD`).
Инициализация графа `0x415AE0` сохраняет исходные значения state 0 и phase 0.
Тикер в `0x402EB0–0x402EBC` обновляет только основной граф `actor+0x08`.
Тень не проигрывает действие основного персонажа и не нуждается в отдельном
цикле по времени.

Во всех восьми Hugo-записях исследованного RU-контейнера auxiliary расположен
по смещению 6684 и содержит одно состояние, один узел, identity transform
типа 3000 и статичный mesh типа 2001. У g006_o0183 это transform o0105 и
mesh o0104. В меше четыре вершины, два треугольника, координаты X/Y от −113
до 113 и Z=0. После масштаба `0.01` и смены осей bounds равны ±1.13 по X/Z,
Y=0. Все восемь текстур 64×64 побайтно совпадают. Материал с флагами
`0x40000000` использует selector 2, то есть `destination * (1-source_rgb)`.
В GLB сохранены исходные texture/color и данные для `HugoNativeMaterials`;
обычного glTF blending для этой формулы недостаточно.

### Положение и изменение размера

В событии рендера `0x22020005` исходник получает мировой transform персонажа,
заменяет только его Z на высоту опоры из `actor+0x24C`, затем умножает все
три столбца basis на один коэффициент (`0x402EF8–0x402F63`):

```text
height_source = actor.physical_z - actor.floor_z
shadow_scale = 1 / (1 + float32(0.0045) * height_source)
shadow_pose = actor.render_transform
shadow_pose.z = actor.floor_z
shadow_pose.basis *= shadow_scale
```

Константа по адресу `0x43E444` равна `0.0044999998062849045`. Для расстояния
в единицах Godot коэффициент равен `0.44999998062849045`, поскольку source
scale равен `0.01`. X/Y берутся из render transform, но высота для формулы —
из физического положения `actor+0x4C`. В исходной render-ветке нет порога
высоты, минимального размера, дополнительной нормализации модели или
поворота по нормали пола. Длительность descriptor тени `3.3333332538604736`
секунды сохраняется как исходное поле, но для воспроизведения не используется.

### Исходная высота опоры и адаптация Godot

Collision interface у `actor+0x2C0` возвращает структуру `actor+0x244`
через virtual `+0x3C = 0x4020A0`; floor Z хранится по смещению `+8`
в этой структуре. Collision update `0x419930` записывает поле в
`0x419F12–0x419F1E` при ненулевом числе ticks; отдельного запрета обновления
для находящегося в воздухе Hugo нет.

Исходный terrain lookup `0x4211E0` проверяет четыре точки `(x±50,y±50)`
в source units и выбирает наибольшую полученную высоту. Подтверждения выбора —
`0x42132D`, `0x4213E0`, `0x42149C`; mesh query `0x414AD0` продолжает поиск
в XY-quadtree `0x414BE0` и треугольниках `0x414530`. Этому запросу не передают
высоту игрока или конечную длину вертикального луча. Наклон поверхности
влияет на найденную высоту, но тень сохраняет basis персонажа. Эта
вспомогательная процедура требует успешного lookup всех четырёх точек;
обработка неудачи относится к окружающему collision solver.

Современный `native_player_presentation.gd` использует четыре вертикальных
запроса к восстановленным native colliders вокруг ног, со смещениями
±0.5 по X/Z, и выбирает самое высокое попадание ниже ног. Это адаптация
опоры для Godot: фильтрация попаданий и разрешение контактов принадлежат
современному движку. Исходные правила для движущихся тел, ступеней и
повторных контактов полностью не эмулируются. Дальность такого запроса
не является восстановленной константой тени. Граф тени получает свой
исходный размер в мире; масштаб высоты основной модели повторно к нему
не применяется. Минимальный размер к формуле не добавляется.

### Общее мигание и исключения при смерти

Исходный render сначала вычитает `actor+0x368` из оставшихся единиц
неуязвимости `actor+0x370` и ограничивает результат снизу нулём
(`0x402E06–0x402E1C`). Затем основная модель и тень вместе пропускаются,
если выполняется условие (`0x402F66–0x402F93`):

```text
(remaining_ticks & 0x20) != 0
and actor.pending_death == 0
and actor.state != 6
```

Используется бит 32 счётчика в исходных единицах 300 ticks/s. Runtime
применяет эту маску к оставшемуся таймеру, скрывая визуальные узлы игрока
и тени вместе. Видимость не меняет физическое тело и продолжение анимации.
Во время отдельного `surface_death_*` тень скрыта: в исходнике state 6 с
ненулевым `actor+0x4C8` рисует только replacement и возвращается раньше
обычного пути (`0x402E22–0x402EA2`). Обычная смерть без replacement использует
основную модель с тенью и не мигает.

Поле `actor+0x4C4` в условии — ожидание смерти после смертельного отбрасывания.
Damage handler записывает его в `0x402833` после ненулевого результата
HealthBar, а `CHugoStateDamage` при приземлении выбирает state 6 вместо
state 0 (`0x403A49–0x403A88`). Это объясняет исключение из мигания, но не
объявляет весь путь смертельного отбрасывания восстановленным в Godot.
Поле и адреса сохранены как доказательство для дальнейшего восстановления
исходного контроллера состояний.

## Деформации мешей

Тип 2001 содержит отдельные массивы вершин и таблицу временных координат.
Один `uint32` таблицы декодируется так:

- Старшие 16 бит — номер сохранённой позы.
- Младшие 12 бит — вес следующей позы в формате Q12, делённый на 4096.
- Биты 12–15 нулевые во всех исследованных мешах.

Например, `0x00050800` означает переход от позы 5 к позе 6 с весом `0.5`.
Последняя поза зацикленного меша может смешиваться с первой. Таблица задаёт
координаты между сохранёнными позами; при промежуточной фазе оригинал сначала
интерполирует соседние координаты таблицы, затем вершины
(`0x414280`, особенно `0x4142D5–0x4143B9`).

Полная проверка исследованного русского контейнера охватила 2 800 мешей,
13 219 записей таблиц, в том числе 2 035 дробных записей и 248 дробных переходов
с последней позы на первую. Выходов за пределы массивов и нарушений Q12 не найдено.

Экспорт сохраняет все позы как glTF morph targets, а исходную таблицу — в JSON.
Godot устанавливает веса blend shapes по этой таблице. `POSITION` каждого
target соответствует исходной деформации, никаких новых промежуточных ключей
в файл не добавляется.

## Ключи преобразований

Тип 2002 оказался таблицей ссылок на текстуры. Он не используется как скелет
или массив преобразований.

| Тип | Заголовок | Данные |
|---:|---:|---|
| 3000 | 52 байта | Постоянные translation и матрица 3×3 |
| 3001 | 68 байт | Ключи положения, по 12 байт |
| 3002 | 64 байта | Сжатые ключи вращения, по 8 байт |
| 3003 | 76 байт | Оба вида ключей с отдельными счётчиками и флагами |

Начальная translation находится по смещению 4, начальная row-major матрица —
по смещению 16. Native применение матрицы `M*v` подтверждено функцией
`0x40BDE0–0x40BE44`. При преобразовании в Godot применяется `(x,z,-y)` и
масштаб `0.01`, а матрица переводится через изменение базиса.

**Положение.** Функции `0x40C850` и `0x40D250` задают кубическую Hermite-кривую.
Касательная внутреннего ключа равна половине разности следующего и предыдущего
положений. На концах незамкнутого пути используется односторонняя разность;
для замкнутого пути соседние индексы переходят через конец массива. Линейная
интерполяция дала бы другие промежуточные положения.

**Вращение.** Декодер `0x42F730` восстанавливает XYZW из четырёх знаковых байтов
первого слова, от старшего к младшему, с делением на 128. Второе слово содержит:

- 10 младших бит: угол в оборотах, делённый на 2048;
- следующие 11 бит: знаковый косинус, делённый на 1024;
- 11 старших бит: обратный синус, делённый на 128.

Интерполятор `0x42FCF0` использует эти сохранённые параметры, включая смену
знака второго кватерниона и линейную ветку при нулевом обратном синусе.
Матрица строится как в `0x40BAD0`. Дополнительная нормализация кватерниона
намеренно не выполняется: она изменила бы исходную байтовую квантизацию.
Проверены все 5 702 поддержанных transform records исследованного контейнера.

## Экспорт и API

```python
from hugo_assets.animation import export_animations

manifest = export_animations(catalog, output_directory)
```

Функция пишет `animation_manifest.json` и `animations/action_00.glb` …
`action_13.glb`, а также 27 `animations/surface_death_*.glb` и отдельный
`animations/hugo_shadow.glb`. Пути относительные.
Профиль содержит 102 отдельных transform tracks, их исходные слова, связи с
мешами, семантику действий и доказательства. Число обычных действий отдельно
сохранено в `hugo_action_count`; дополнительные графы перечислены в `surface_deaths`.
Материалы и текстуры берутся только из локального ресурса пользователя.

Поле `hugo_shadow` содержит относительный путь, source owner/mesh/transform,
смещение исходного графа, постоянную фазу, bounds и `render_policy` с формулой
масштаба и условиями видимости. Тень экспортируется через
`export_hugo_shadow(catalog, output_directory, owner)` с запечённым локальным
статическим transform. Она не добавляется к `clips` или `bindings`: остаются
41 анимационный клип и 42 файла GLB. Синтетические тесты в
`tests/test_hugo_shadow.py` проверяют статический экспорт, локальную позу,
native blend и отказ от неподтверждённых вариантов графа.

`HugoPlayerVisual` автоматически обнаруживает manifest рядом с `hugo.glb`.
Модель получает один постоянный масштаб из границ исходной позы ожидания;
высота исходной сборки в масштабе `0.01` — `3.33077171665`. Меняющаяся поза не
меняет размер персонажа. Если manifest отсутствует, остаётся статический GLB,
а без локальных игровых данных — геометрический заменитель.

Основные методы `HugoOriginalAnimation`:

```gdscript
load_manifest(path: String, material_fix: Callable) -> bool
set_action(action: String, restart: bool = false) -> void
advance(delta: float, traveled_distance: float = 0.0) -> void
seek_phase(phase: float) -> void
seek_native_tick(tick: float) -> void
```

`seek_native_tick` переводит значение через **исходную авторскую длительность**;
для движений, управляемых расстоянием, точная адресация позы — `seek_phase`.
Завершение незамкнутого действия сообщает сигнал `action_finished`.

Тот же класс предоставляет общий сэмплер для платформ и других акторов:

```gdscript
sample_native_transform(track: Dictionary, phase: float) -> Transform3D
sample_native_path_tangent(track: Dictionary, phase: float) -> Vector3
to_godot_transform(source: Transform3D, source_scale: float = 0.01) -> Transform3D
apply_native_morph(node: MeshInstance3D, data: Dictionary, phase: float) -> void
```

Первый метод возвращает координаты исходной игры. Цепочка преобразований
собирается от владельца к дочернему объекту, затем один раз переводится в Godot.
`apply_native_morph` принимает `stored_samples`, `timeline_words`,
`timeline_loop`. Сэмплер можно создать без загрузки Hugo manifest.

Godot 4.7 оставлял флаг COLOR_0 выключенным у первых поверхностей некоторых
импортированных мешей. Загрузчик исправляет флаг на **копиях материалов**;
исходные GLB и общие ресурсы не меняются.

## Контроллер и ограничения

Клавиши приседания и удара задаёт центральная карта ввода. Тестовая сцена
использует капсулу, масштабируемую по высоте модели. Оригинальная кампания
подключает восстановленные параметры через `set_native_configuration`; тогда
тело имеет исходные размеры `0.8 × 3.0 × 0.8`, в приседе — `0.8 × 2.0 × 0.8`.
Перед подъёмом проверяется место под полную стоячую форму. Визуальная высота
`3.33077` сохраняется отдельно. Формулы движения, доказательства и ограничения
описаны в [player_recovery.md](player_recovery.md).

`attack_started`, `hurt_received(amount)` и `apply_damage(amount, knockback)`
служат связью с игровым миром. Здоровье и жизни хранит мир. Повторный контакт
во время неуязвимости отклоняется; получение урона прерывает удар. Исходная
неуязвимость длится 600 единиц таймера, или две секунды; урон от 1000 обходит
её (`0x40274B`, `0x402E12`). `attack_serial` увеличивается при каждом принятом
ударе и даёт миру исходный принцип устранения повторных попаданий одного удара.

`get_native_visual_action`, `get_native_visual_phase` и
`get_native_visual_transform` предоставляют действие, фазу и глобальную базу
исходного графа для областей столкновения и эффектов. База включает постоянный
масштаб и поворот модели; локальные source transforms надо перевести через
`to_godot_transform`, затем домножить на неё.

При `native_reset_handling` падение и клавиша сброса отправляют один
`reset_requested("fall"/"manual")`, а восстановлением мира управляет уровень.
`play_death` запускает исходное действие 13, возвращает его длительность и
сообщает завершение сигналом `death_animation_finished`. `respawn` очищает
временные состояния и возвращает управление, сохранённое до смерти.

Восстановленные клипы доступны полностью, однако переключение между ними
пока не воспроизводит весь исходный контроллер сглаживания состояний. Отдельно
доступны дополнительное ожидание, приземление, двунаправленный переход
приседания и смерть. Автоматический выбор редких действий зависит от реализации
мира. Анимация текстур, цветов и UV восстановлена отдельно, как описано ниже.
Ссылки на эффекты,
не являющиеся мешами, сохранены в `omitted_effects`; их воспроизводит отдельная
система эффектов уровня.

## Материалы и их исходная анимация

`HugoNativeMaterials` загружает `material_animation_manifest.json` и связывает
каждую поверхность по имени `__hugo_anim_g###_r####_p###__hugo_blend_N`.
В экспортированных ресурсах сохранены 483 анимированные части: 285 текстурных
последовательностей, 190 цветовых и восемь UV-анимаций. Повторяющиеся кадры
текстур остаются отдельными слотами исходной последовательности.

Обычные меши используют следующий selector из `(part.flags >> 29) & 3`.
Его значения отличаются от enum системы частиц.

| Selector | Формула RGB | Запись глубины |
|---|---|---|
| 0 | `source * alpha + destination * (1-alpha)` | Нет |
| 1 | `source + destination` | Нет |
| 2 | `destination * (1-source)` | Нет |
| 3 | `source` | Да |

Источник: извлечение selector `0x412E9B`, очередь `0x411D10`, состояния D3D
`0x41090A–0x410991`. Общая alpha-проверка отбрасывает только значения меньше
`8/255` (`0x40F385–0x40F3A6`). Чёрный RGB не считается прозрачностью.
Текстура умножается на исходный RGB/255, без дополнительного усиления
(`COLOROP=MODULATE`, `0x40F3D2`). Обычные текстурированные вершины имеют alpha=1,
нетекстурированные — `128/255`; четвёртый исходный цветовой байт не является alpha.

Текстурный кадр равен `trunc(float32(visual_phase) * count) % count`. Точная
фаза 1 выбирает кадр 0 даже у незамкнутого morph-клипа. Цвета и UV используют
тот же Q12 timeline, что и геометрия. Цветовая интерполяция включена исходным
флагом `0x04000000`, после неё каналы усекаются до целых байтов. Красный канал
сохраняет точность x87 до усечения, зелёный и синий предварительно сохраняются
как float32 (`0x413121`, `0x413165`). Это различие воспроизведено: переход
109→29 при весе `float32(0.15)` даёт `[96,97,97]`.

UV линейно смешиваются без округления до байта и без сокращения пути через
границу текстуры, затем умножаются на исходное `float32(1/255)`. Изменение
текстуры использует исходную visual phase, независимо от числа сохранённых
геометрических поз. `OriginalAnimation` и `NativeActorMotion` передают одну
и ту же фазу геометрии и материалу; отдельного придуманного FPS здесь нет.

Импортёр Godot может переставить вершины. Поэтому экспортёр сохраняет
`TEXCOORD_1 = [source_vertex_index, source_part_index]`. Для RGB/UV runtime
создаёт один частный ArrayMesh, копирует все поверхности и morph targets,
затем обновляет только буфер атрибутов. UV2 и геометрия при этих обновлениях
не меняются. Текстурные последовательности не требуют копирования меша.
Общие импортированные ресурсы остаются неизменными.

Проверка полноценного Godot editor import всех 198 RGB/UV частей сохранила
все 7044 исходных индекса вершин. Изолированная проверка выполнила 1063 проверки
на синтетических и исходных примерах: Q12/float32, конечные фазы, байтовые RGB,
UV, файлы текстур, сохранение morph/геометрии и чтение обновлённых буферов
обратно из OpenGL Compatibility. Постоянный тест без исходных игровых ресурсов:

```bash
godot --headless --path game --script res://tests/native_material_test.gd
```

Godot обслуживает сортировку прозрачных поверхностей и растеризацию. Исходный
D3D rasterizer и порядок всех внутренних очередей не эмулируются побитово.

## Исходная камера

`HugoNativeCamera` наследует публичный интерфейс обычной камеры:

```gdscript
configure(gameplay_camera: Dictionary, native_transform_tracks: Dictionary) -> bool
set_target(player: Node3D) -> void
receive_native_event(event: Dictionary) -> bool
set_manual_orbit(enabled: bool) -> void
native_checkpoint_snapshot() -> Dictionary
restore_native_checkpoint(saved: Dictionary) -> bool
```

Поля `camera` и `controls_enabled` доступны так же, как у `HugoFollowCamera`.
Правая кнопка мыши включает ручную орбиту, действие `camera_toggle` возвращает
исходный путь. Публичная `native_phase` продолжает отслеживать персонажа и
при ручном обзоре, поскольку исходный progress для областей активации акторов
равен `trunc(native_phase * 992.0)` (`0x40A8C5–0x40A901`, константа `0x43E6D8`).
При отсутствии исходных путей остаётся обычная камера.

Исходный checkpoint камеры занимает 52 байта: фаза tracker и 12 float мирового
положения/матрицы (`0x40A735–0x40A753`, восстановление `0x40A7A1–0x40A7BD`).
Современный snapshot сохраняет эти данные в JSON-compatible полях
`native_phase`, `camera_position` и `camera_basis` (три столбца). Restore
возвращает фазу и pose сразу, отключает ручную орбиту и не вызывает snap,
который заменил бы восстановленную фазу. Pitch smoothing и таймер временного
эффекта не добавлены в checkpoint: исходный serializer их не записывает.

У `CTargetCam` есть два разных transform: основной путь задаёт положение камеры
(`owner+0x1C`), дополнительный путь отслеживает положение персонажа
(`owner+0x28`). Это подтверждают конструктор `0x40A4E2–0x40A52F`, инициализация
`0x40AE06–0x40AE37` и обновление `0x40A888–0x40A966`. Положение цели берётся из
исходной позиции персонажа, без добавленной высоты головы (`CHugoMainActor`,
virtual `+0x1C`, функция `0x403400`).

`CSnapTracker` (`0x40CE60`) ищет от предыдущей фазы интервал между плоскостями
касательных ключей. Внутри интервала выполняются десять двоичных уточнений с
линейно смешанными положениями и нормализованными касательными. Это не поиск
ближайшей точки по евклидовому расстоянию и не привязка к ближайшему ключу.
Добавлен ограничитель числа проходов для вырожденного замкнутого пути.

Положение камеры сэмплируется исходным Hermite-интерполятором. Направление
взгляда дополнительно смещается к касательной основного пути, если камера
смотрит вдоль неё: вес равен `0.5 * max(dot, 0)^2`
(`0x40AB38–0x40AC18`). Для касательной используется отдельная производная
четырёхточечного кубического полинома (`0x40CA10`, `0x40CC30`). Вертикальный
угол приближается к цели на `0.01` оставшейся разницы за единицу исходного
таймера (`0x40AC67`). При первом появлении камера сразу получает целевой угол;
начальный переход от исходной четверти оборота не воспроизводится.

FOV исходного ресурса горизонтальный. `Camera3D.KEEP_WIDTH` и значение из
manifest проверены по фактической матрице Godot при 1280 × 720, а не только
по имени свойства. При формате не шире 16:9 применяется точный исходный
горизонтальный FOV. В версии 0.3 для более широких окон горизонтальный обзор
расширяется с сохранением вертикального обзора 16:9: это предотвращает
обрезание персонажа в прыжке. Исходный FOV в данных, траектория, tracker
и поза камеры не меняются. `native_camera_aspect_test.gd` проверяет матрицу
настоящего viewport, изменение размера и возврат к исходному формату.

Событие `0x22000009` включает временный transform-эффект. Его source translation
X прибавляется к source Z **и камеры, и цели**; путь камеры не переключается
(`0x40AD95–0x40ADEB`). Период берётся из float-битов `param2`, повторное событие
во время активного эффекта игнорируется, после полного периода эффект снимается.
В исследованном ресурсе шесть таких уведомлений относятся к финальной погоне
и используют transform группы 69, объект 7, с периодом одна секунда.

Изолированная проверка Godot прошла 248 проверок на данных восьми камер:
40 положений на путях, конечные координаты, горизонтальная проекция, переход
в ручной режим и обратно, обновление tracker при ручном обзоре, JSON round-trip
checkpoint, вертикальное смещение, запрет наложения и завершение эффекта.
На точной плоскости ключа float32 может выбрать соседний результат
последнего двоичного уточнения; это ограничение точности, а не новая привязка.

## Проверки

```bash
python -m unittest discover -s tests -p 'test_*.py' -v
```

Синтетические тесты проверяют Q12, замыкание последней позы, пределы массивов,
порядок и знак компонентов вращения, packed slerp, Hermite и повреждённые ключи.
Исходные игровые байты в тестах не хранятся.

Локальная проверка в Godot 4.7.2 загрузила все 41 GLB и сравнила 620 положений
мешей с независимым Python-сэмплером: максимальная разница компонентов матриц
составила `1.8e-7`, положения — `2.9e-7`; веса morph targets совпали точно.
Ещё 165 проверок охватили все 27 профилей смерти: исходную длительность,
промежуточную фазу, завершение, очистку при возрождении и обычную смерть при
неизвестной ссылке.
Отдельно проверены ввод приседания под потолком, подъём после освобождения
места, одиночный сигнал удара, защита от повторного урона и сброс состояний при
возрождении. Рендер проверяется на реальных GLB, без запуска оригинального EXE.
